<Warning>
  **There is no 2026.9 Navisworks desktop connector.** **2026.8** was the last one and is
  deprecated. Upload NWC and NWD files instead: ingestion takes files up to **2 GB**.
</Warning>

## Choose how to publish

- **Upload a file.** Upload an **NWC** or **NWD** file. Speckle parses the file on the server, so
  you do not leave Navisworks open on a publish progress bar. Ingestion takes files up to **2 GB**.
  See [Direct uploads](/connectors/direct-uploads/introduction).
- **Files in Autodesk cloud storage.** Sync NWC and NWD files from ACC. ACC sync of Navisworks files
  has been tested to **6 GB**. See [Autodesk Forma Data Management
  (ACC)](/connectors/cloud-integrations/acc).

<Warning>
  A file uploaded directly and the same model published from the desktop connector do not produce
  identical Speckle data. See [Uploads and connectors produce different
  datasets](/connectors/direct-uploads/introduction#uploads-and-connectors-produce-different-datasets).
</Warning>

If a file is larger than the upload or ACC sizes above, or you have a workflow that only the desktop
connector can do, tell Speckle in [speckle.community/help](https://speckle.community/help).

## Data format of a 2026.8 publish

The 2026.8 connector publishes the data model from before 2026.9. Speckle may convert that version
to the 2026.9 format on the server. Treat that conversion as best effort, not a guarantee.

- In the web app, versions stay readable either way.
- Speckle Intelligence can query only versions that are in the 2026.9 format. See [Ask questions
  about your models with Speckle Intelligence](/analytics/intelligence).
- If you read this data in a script, notebook, Automate function, or other API consumer, follow
  [Data model migration for developers](/developers/migration/data-model-migration). Do not assume
  the version was converted, and do not assume it stayed on the earlier model.

NWC and NWD uploads use the 2026.9 format, or the earlier format if the workspace is in
compatibility mode. Compatibility mode does not apply to desktop connector publishes. See
[Compatibility mode](/it-admin/compatibility-mode).

## Publish from the 2026.8 connector

<PublishOnly app="Navisworks" />

<AccordionGroup>

<Accordion title="What types of elements can I publish from Navisworks to Speckle?">
  All visible objects in the Navisworks scene can be published to Speckle. This includes geometry
  from appended NWC, DWG, IFC, and RVT files. The export includes: - object geometry (as meshes) -
  model hierarchy - attached properties (from source files) - file metadata
</Accordion>

  <Accordion title="Can I publish only selected objects or specific appended files?">
    You can publish any of the following:

    <ul>
      <li>A manual selection of objects, which can include a file in the scene.</li>
      <li>A saved selection set</li>
      <li>A saved search set</li>
      <li>A saved view</li>
    </ul>

    Use the connector UI to choose which of these to send to Speckle.

  </Accordion>

<Accordion title="Can I include saved timeliner information, redlines, or clash results?">
  Not at this time. The Navisworks connector currently focuses on object geometry and properties.
  Markups and clash results are not exported.
</Accordion>

<Accordion title="Can I preserve selection sets or search sets when publishing?">
  While selection and search sets themselves are not preserved as named sets in Speckle, as that
  concept doesn't yet exist on the web, you can use them as filters to choose what objects to send.
  The objects they reference will be exported with full geometry and metadata.
</Accordion>

<Accordion title="How do I ensure my Navisworks model is correctly positioned in Speckle?">
  The connector uses the world coordinate system as defined in Navisworks. If your model has an
  offset origin, it will be preserved in the Speckle model. To align with other models, ensure a
  consistent shared coordinate system.
</Accordion>

<Accordion title="My Navisworks model is in real-world coordinates, how can I move it closer to the origin?">
  You can use the **Transform** option in the Speckle connector to apply a translation to your model
  before publishing. This allows you to adjust the position without modifying the original
  Navisworks file.
</Accordion>

<Accordion title="Do custom properties (e.g., element metadata or quantities) get published?">
  Yes. All custom properties attached to elements in Navisworks are included in the Speckle export.
  These can be viewed in the Speckle web viewer by selecting an object and inspecting its
  properties.
</Accordion>

<Accordion title="Will properties added with DataTools be sent?">
  Yes, any properties added to objects using DataTools in Navisworks will be included in the export
  to Speckle. Ensure the properties are visible in the object inspector before publishing.
</Accordion>

<Accordion title="Can I export the model as a tree structure or a flat list?">
  By default, the connector exports objects as a flat list. If you want to preserve the model's
  hierarchy (tree structure), enable the **Preserve Hierarchy** option in the connector UI before
  publishing. Regardless of this setting, all elements will include a <code>path</code> property
  that records their original hierarchy within the model.
</Accordion>

## FAQ

<AccordionGroup>
  <Accordion title="Will there be a 2026.9 Navisworks connector later?">
    Not as of now. If a file above the upload or ACC sizes, or a desktop-only workflow, blocks you,
    post in [speckle.community/help](https://speckle.community/help) so it can be considered.
  </Accordion>
  <Accordion title="Why is there no 2026.9 desktop connector?">
    The desktop connector cannot match the throughput of server-side NWC and NWD ingest on large
    files. Speckle does that processing so you do not watch a progress bar in Navisworks. The 2026.8
    connector is deprecated and is not guaranteed to keep working with current servers.
  </Accordion>
  <Accordion title="Should I update the Navisworks connector in the 2026.9 upgrade window?">
    No. There is no 2026.9 Navisworks package. Keep the 2026.8 connector, and update your other
    connectors as usual. See [Upgrade window for
    2026.9](/it-admin/connector-updates#upgrade-window-for-2026-9).
  </Accordion>
</AccordionGroup>
