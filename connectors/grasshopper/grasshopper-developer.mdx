## Using a developer access token for authentication

If you are using Speckle for Grasshopper in a headless Rhino environment such as Rhino Compute, or you want access to a Speckle account via developer access token, you can use the **Speckle Model URL with Token** node from the **Dev** category.

<Frame>
  <img src="/images/connectors/grasshopper/node_modeltoken.jpg" alt="Node modeltoken" />
</Frame>

<Note>
  The developer token used must have the following scopes enabled: `profile:read`, `profile:email`,
  `stream:read`, and `workspace:read` (unless on a non-workspace enabled server), as well as any
  other write scopes needed
</Note>

Inputs:

1. Add the **Speckle URL** input to the Speckle Model you want to create a resource for.
2. Add the **Speckle Token** input string of your developer access token.
   Tokens can be created [in the Speckle app](https://app.speckle.systems/settings/user/developer) with your desired permissions.

Outputs:

1. The **Speckle Model** output contains the Model resource of your input URL.

## Inspecting all attributes on Speckle params

Use the **Deconstruct** node to access every field of a Speckle param in Grasshopper, such as its application ID, geometric attributes like the knot vector of a NURBS curve, and any dynamically attached attributes.

To find what an object is connected to, such as its level, rooms, or host, use the [Explore](/connectors/grasshopper/explore) node instead. In the web app, the [Inspector](/3d-viewer/exploration#inspect-raw-data-and-relations) panel shows the relations and raw properties of a selected object.

<Info>
  **Inspect → construct → exchange:** Deconstruct is the **inspect** layer (one object on a wire).
  To **construct** rich graphs with computed metadata and nested collections in C#, see [Enrich
  Speckle data in
  Grasshopper](/developers/sdks/dotnet/guides/use-speckle-sdk-in-grasshopper-csharp). **Publish** on
  the connector is the **exchange** layer when you are ready to move data.
</Info>

<Frame>
  <img src="/images/connectors/grasshopper/node_deconstruct.jpg" alt="Node deconstruct" />
</Frame>

Inputs:

1. Add a **Speckle Param** input of any Speckle parameter you would like to inspect.

Outputs:

1. An output will be created for every direct attribute on the input Speckle Param.

Additional Settings:
`Right-click` an output param for additional settings:

- Select **extract parameter** to automatically create a new param node with the value and name of the output param.

<Warning>
  This node is intended for attribute inspection on individual objects, or on lists of objects of
  the same Speckle type. If you would like access to properties across different objects, please
  request this to be added to our passthrough nodes on our forum.
</Warning>

## Synchronous operations

For any scripts operating in contexts which require synchronous solving of nodes, use the **(Sync) Publish** and **(Sync) Load** nodes instead of the default Publish and Load nodes.

## Using Speckle with C#/Python script nodes

### C# script

Speckle publishes nuget packages for our C# SDK. You will need to install the following nugets for your custom C# script:

- Use the [Speckle.Sdk](https://www.nuget.org/packages/Speckle.Sdk) nuget for publish and load operations, serialization, core objects classes like **Base** and **Collection**, and more.
- Use the [Speckle.Objects](https://www.nuget.org/packages/Speckle.Objects) nuget for access to all geometry and additional object classes.

<Frame>
  <img src="/images/connectors/grasshopper/developer_csharp.jpg" alt="Developer csharp" />
</Frame>

To install them in a C# script node:

1. Add a C# script node from **Maths** > **Script**, and double-click it to open the script editor.
2. Select the box icon to install a third-party package.
3. Paste these references into the **Specify Package(s)** field and select **Install**.

```csharp
#r "nuget: Speckle.Sdk, 2026.9.0-beta.7"
#r "nuget: Speckle.Objects, 2026.9.0-beta.7"
```

When a stable 2026.9.0 release is out, use that version instead.

### Python script

The Python SDK, [specklepy](https://pypi.org/project/specklepy/), needs Python 3.11 or later. Whether
you can use it inside Grasshopper depends on the Rhino runtime:

- **Rhino 8:** its Python 3 engine is CPython 3.9.11, below specklepy's minimum. Use the C# route
  above or run specklepy in a separate Python environment. See [What is
  Rhino.Python?](https://developer.rhino3d.com/guides/rhinopython/what-is-rhinopython/).
- **Rhino 9 WIP:** its new Python 3 ScriptEditor uses CPython 3.13.4 under
  `~/.rhinocode/py313-rh9`, so it can run current specklepy. Use the new Python 3 Script component;
  scripts marked `#! python3` or saved with a `.py3` extension use that runtime. See McNeel's [Python
  3.13 announcement](https://discourse.mcneel.com/t/rhino-beta-feature-python-3-13/205209) and [Rhino
  9 WIP runtime report](https://discourse.mcneel.com/t/scripteditor-rhino-wip-9/214039).
- **Legacy GhPython:** the old component uses IronPython 2.7 and cannot run current specklepy. It is
  separate from the new ScriptEditor components. See [Grasshopper scripting with
  Python](https://developer.rhino3d.com/guides/scripting/scripting-gh-python/).
