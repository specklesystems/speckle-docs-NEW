Speckle 2026.9.0 changed two things: how you **publish and load** models, and how objects **hold their name and properties**. Both changed by adding new nodes alongside the ones you already have, so your existing scripts keep working exactly as they did and there is nothing you have to do today.

This page covers what changed, and what to check when you are ready to move a script across.

<Note>
  Nothing is removed from your canvas and no wires break. The nodes you already have are renamed and
  hidden from the ribbon, not deleted.
</Note>

## What changed

Every node below was added or renamed rather than altered, so nothing on your canvas shifts under you.

### Publishing and loading

| Node on your canvas                  | What it does now                                                  |
| ------------------------------------ | ----------------------------------------------------------------- |
| `Load` / `Publish`                   | The current nodes. Support Speckle 2026.9.0 onwards.              |
| `Load (legacy)` / `Publish (legacy)` | Your existing nodes, renamed. Still work, hidden from the ribbon. |

The same applies to `(Sync) Load` and `(Sync) Publish`.

### Objects

| Node on your canvas         | What it does now                                                       |
| --------------------------- | ---------------------------------------------------------------------- |
| `Speckle Data Object`       | Renamed **Speckle Object**. Same node, same ports, back in the ribbon. |
| `Speckle Geometry (legacy)` | Your existing Speckle Geometry node, renamed. Still works, hidden.     |
| `Speckle Geometry`          | New. Geometry, colour and material - no Name or Properties. See below. |

A **Speckle Object** holds one name, one set of properties, and one or more geometries. Name and properties moved onto it, and off geometry - see [Where Name and Properties went](#where-name-and-properties-went).

## Do I need to upgrade?

| If you...                                                            | Then...                                                           |
| -------------------------------------------------------------------- | ----------------------------------------------------------------- |
| have scripts that work and you are not changing them                 | Nothing to do. Leave them alone.                                  |
| are building a new script                                            | You already have the current nodes; the ribbon only offers those. |
| want the [Explore node](/connectors/grasshopper/grasshopper-explore) | Upgrade the script's Load node.                                   |
| load a version published by an upgraded teammate                     | Upgrade the script's Load node.                                   |

## Upgrade a script

<Steps>
  <Step title="Add the current Load node">
    Place a `Load` node from the ribbon and move your Speckle Model wire onto it. Its `Collection`
    output goes where the old one went.
  </Step>
  <Step title="Reconnect anything downstream">
    Check the nodes reading that Collection still resolve. Objects come through as **Speckle
    Objects** rather than Data Objects - the same shape under a new name - so most wires carry
    straight over. See [What the output looks like](#what-the-output-looks-like).
  </Step>
  <Step title="Delete the old node">
    Remove the `Load (legacy)` node once nothing is wired to it.
  </Step>
  <Step title="Repeat for Publish, if your script publishes">
    Read [Before you switch Publish](#before-you-switch-publish) first - this one affects your
    collaborators, not just you.
  </Step>
</Steps>

## What the output looks like

The current Load node reflects how models are stored now, so some outputs differ.

| Output       | `Load (legacy)`                    | `Load`                       |
| ------------ | ---------------------------------- | ---------------------------- |
| `Collection` | Data Objects and geometry          | Speckle Objects and geometry |
| `Properties` | Model-wide properties              | Model-wide properties        |
| `Proxies`    | Materials, colours, levels, groups | Not available - see below    |

A **Speckle Object** is what a Data Object was: one name, one set of properties, and one or more geometries. An element that arrived as one item still arrives as one item, so a wall with three meshes does not become three walls.

Nothing else is lost either. Materials and colours arrive on each object rather than in a side list, and levels, rooms, hosts and definitions are reachable through the [Explore node](/connectors/grasshopper/grasshopper-explore).

<Note>
  You may see slightly more objects than before. Elements that carry only properties and no geometry
  - Revit rooms, levels and areas - now come through where they were previously skipped.
</Note>

## Where Name and Properties went

The new `Speckle Geometry` node has no Name or Properties inputs. They belong to the **Speckle Object** that contains the geometry, not to the geometry itself.

This is why: a wall is one thing with one name and one set of properties, and three meshes. If each mesh carried its own copy, summing a volume across your model would count that wall three times. Putting them on the object means one wall, one volume, however many meshes it happens to have.

To set a name or properties, wire your geometry into a `Speckle Object` and set them there.

<Note>
  Your existing scripts still work. The `Speckle Geometry (legacy)` node keeps its Name and
  Properties inputs, and geometry that already carries them keeps carrying them.
</Note>

## Before you switch Publish

Versions from the current `Publish` node need an upgraded connector to read. Versions from `Publish (legacy)` can still be read by older connectors, which is why it is still available.

If people consume your model in another application, confirm they have upgraded before you switch. If you are not sure, leave Publish on the legacy node and upgrade Load only - the two are independent.

## Do not mix generations in one script

If your script publishes and then reloads in the same definition, use the current nodes for both. A version created by the current `Publish` node cannot be read by a `Load (legacy)` node.

## Messages you might see

| Message                                                              | What it means                                                             |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| This Load component is deprecated                                    | You are on a legacy node. Nothing is wrong; upgrade when convenient.      |
| This version was published before Speckle 2026.9.0                   | An older version loaded fine. Grouping and collection paths may differ.   |
| This version needs the current Load component                        | A legacy node hit a version it cannot fully read. Upgrade the node.       |
| Versions published by this component can be read by older connectors | A reminder from `Publish (legacy)`. Check collaborators before switching. |
| The name or properties on the incoming geometry were replaced        | The Speckle Object's name and properties win. Set them on the object.     |
| Replacing the geometry dropped its properties                        | Swapping a shape does not carry properties across. Use a Speckle Object.  |

## Frequently asked

<AccordionGroup>
  <Accordion title="Will my saved scripts break?">
    No. Nodes are matched by identity, not by name, so renaming them has no effect on your files. No
    node turns into a placeholder and no wire is dropped.
  </Accordion>
  <Accordion title="Why can't I find Load in the ribbon anymore?">
    You can - it is the same place it always was. The node named `Load (legacy)` is the hidden one,
    and the `Load` in the ribbon is the current node.
  </Accordion>
  <Accordion title="Can I copy a legacy node from an old script?">
    Yes, copy and paste still works. It is worth replacing it with the current node instead, so the
    script does not carry the older behaviour forward.
  </Accordion>
  <Accordion title="Do I have to upgrade Load and Publish together?">
    No. They are independent. Upgrading Load only is a good first step, since it affects nobody but
    you.
  </Accordion>
  <Accordion title="What happened to the Speckle Data Object node?">
    It is now called **Speckle Object** and is back in the ribbon. Same node, same ports, same
    behaviour - it just no longer shows a deprecation message on every solve.
  </Accordion>
  <Accordion title="Why does my Speckle Geometry node have fewer inputs?">
    It does not. The node in your script is `Speckle Geometry (legacy)` and keeps all of its inputs.
    The `Speckle Geometry` in the ribbon is a new node without Name and Properties - see [Where Name
    and Properties went](#where-name-and-properties-went).
  </Accordion>
</AccordionGroup>
