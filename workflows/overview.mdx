These guides show how Speckle capabilities fit together to produce real outcomes. Capabilities describe what Speckle can do; the pages in this section show how to combine them in practice.

<Note>
  The [Speckle website](https://speckle.systems) also uses **Workflows** for high-level solution areas—for example [project dashboards and progress tracking](https://speckle.systems/project-dashboards-and-progress-tracking), [present and review models](https://speckle.systems/present-and-review-models), and [exchange design data](https://speckle.systems/exchange-design-data). **Here**, each page is a detailed, repeatable workflow you can follow in the product.
</Note>

## Common foundation

All workflows in this section assume a shared baseline for how data is stored and evolved:

<Note>
  **Foundation:** Data lives in [Projects](/workspaces/projects), [Models](/workspaces/models), and [Versions](/workspaces/versions). Versions are immutable and form a complete history. Work proceeds by reading data, transforming it as needed, and publishing new versions.
</Note>

## What is a workflow?

A workflow in this section is not a single feature or connector. It is a repeatable pattern that combines multiple capabilities to achieve a specific outcome in a defined context.

Each workflow answers:

- **What outcome** does this achieve?
- **What capabilities** are composed?
- **In what context** is this used?

## Common patterns

Workflows here often fall into a small set of patterns:

### Observation

Understand and review model data without modifying it.

**Examples:** Design review and coordination.

### Evaluation

Assess model data against rules or criteria to produce signal.

**Examples:** Model validation and rule checking.

### Transformation

Modify, restructure, or derive new data from existing models.

**Examples:** Grasshopper-based data shaping and generation.

### Extraction

Use model data outside Speckle for reporting, analytics, or integration.

**Examples:** Data extraction with SpecklePy for Power BI or external systems.

### Reconstruction

Reinterpret Speckle data into native elements in a target system.

**Examples:** Mapping geometry to native Revit families and types.

## Using this section

Start from the **outcome** you want rather than the tool you are using.

These workflows are patterns, not rigid pipelines. In practice you will often combine them—for example, evaluation may feed reconstruction, or transformation may precede extraction.
