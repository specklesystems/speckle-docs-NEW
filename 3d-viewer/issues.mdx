## What are issues?

Issues let you report problems, request changes, and track feedback on your models. Raise an issue
from the 3D viewer and it stores the view you were looking at, so anyone who opens it sees the same
thing. Assign it, set a priority and due date, and track it until it is resolved.

## Create an issue in the viewer

<Steps>
  <Step title="Set up the view">
    Open the model, frame the camera, and select the objects the issue is about.
  </Step>
  <Step title="Start a new issue">Open **Issues** (Shift+I) and select **New issue** (**+**).</Step>
  <Step title="Fill in the issue">
    Enter a title. Add a description, status, priority, assignee, due date, labels, or a file as
    needed.
  </Step>
  <Step title="Create the issue">
    Select **Create issue**. You should see the issue in the list, with a preview of the view.
  </Step>
</Steps>

The issue stores the camera, filters, visibility, and selection at the moment you create it. With
nothing selected, it stores the view only. To raise an issue that is not tied to a view, select **New
issue** on the project's **Issues** page instead.

<AccordionGroup>
  <Accordion title="Can I create an issue without selecting an object?">
    Yes. An issue raised with nothing selected stores the camera, filters, and visibility. An issue
    created from the project's **Issues** page has no stored view.
  </Accordion>
  <Accordion title="How do I mark up the model for an issue?">
    Draw with [Sketch](/3d-viewer/markups) before you select **Create issue**. The issue's preview
    image is captured with your sketches and measurements. You can also attach an image file.
  </Accordion>
  <Accordion title="What if I need to reference multiple objects in one issue?">
    Select all relevant objects before you create the issue. Hold Shift while clicking to select
    more than one.
  </Accordion>
</AccordionGroup>

## Issue fields

Each issue has fields to help you organize and prioritize work.

<Frame>
  <img src="/images/3d-viewer/issues-window.png" alt="Issues window" />
</Frame>

### Title and description

The title is required. The description is optional plain text.

### Status

Track progress with three statuses:

- **Open** - the issue needs attention (default)
- **Ready for Review** - the work is done and needs checking
- **Resolved** - the issue is closed

**Resolve issue** and **Reopen issue** in the issue header change the status in one step.

### Assignee

People with the **Viewer** role or higher can create issues, reply, and be assigned to issues. For a private
project, an assignee must already have access to that project; ordinary workspace membership alone
is not enough. Assigned users receive an email notification.

### Due date

Set a date when the issue should be resolved. Use the **Overdue** filter to find issues past their
due date.

### Priority

Indicate urgency with four levels: **No priority** (default), **Low**, **Medium**, **High**.

### Labels

Tag an issue with one or more labels to group issues by discipline, phase, type, or any other
criteria. Workspace admins manage labels in **Workspace settings** → **Issue labels**, and labels
are shared across all projects in the workspace.

<Note>
  Priority, assignee, due date, and labels are available only on projects that belong to a
  workspace.
</Note>

<AccordionGroup>
  <Accordion title="Can I change fields after creating an issue?">
    Yes. Open the issue and change its status, priority, assignee, due date, or labels, if your role
    allows it. The title and description cannot be edited in the web app after you create the issue.
  </Accordion>
  <Accordion title="What happens if I delete a label that's used on issues?">
    The label is removed from all issues using it. Consider renaming or recoloring labels instead of
    deleting them if they're actively used.
  </Accordion>
</AccordionGroup>

## Reply and attach files

### Replies

Write a reply at the bottom of an issue, in the **Issues** panel or on the issue page. Press
Cmd/Ctrl+Enter to send. Replies appear in order below the description. Anyone with the **Viewer**
role or higher on the project can reply.

### Attachments

- When you create an issue, select **Attach file** to add one file.
- On the issue page, attach a file to a reply with the paperclip.

Attachments help clarify problems visually and provide reference material for the fix.

<AccordionGroup>
  <Accordion title="Is there a file size limit for attachments?">
    Individual attachments are limited to a reasonable file size to ensure performance. If you need
    to share large files, link to them in cloud storage.
  </Accordion>
  <Accordion title="Can I attach files from my desktop apps like Revit?">
    Not directly from the connector. Attachments can only be added in the web app.
  </Accordion>
  <Accordion title="What file types can I attach?">
    Most common file types are supported, including images (PNG, JPG, etc.), PDFs, and office
    documents.
  </Accordion>
</AccordionGroup>

## Find and manage issues

### Issues panel in the viewer

<Frame>
  <img src="/images/3d-viewer/issues-panel.png" alt="Issues panel" />
</Frame>

**Issues** lists the issues for the models in the scene. Each card shows the status, title, author,
priority, reply count, and assignee. Issues marked **Resolved** are hidden by default to keep the
list focused on active work.

Select **Filter issues** in the panel header to filter by:

- Status
- Priority
- Assignee
- Labels
- Overdue

Select **Search issues** to find an issue by text. When nothing matches the search or filters, the
panel shows **No matching issues**. Select an issue to open its details and replies; the viewer
restores the view stored with it. In a wide panel, **Select an issue** marks the details area until
you pick one. Right-click a card, or use **⋯**, for **Open issue
page**, **Copy link**, and **Delete…**.

<AccordionGroup>
  <Accordion title="Can I see issues from multiple models at once?">
    Yes. If you've loaded several models into the viewer, **Issues** shows issues from all of them.
  </Accordion>
  <Accordion title="Why don't I see an issue I know exists?">
    Check your filters. Issues with status **Resolved** are hidden by default, and other filters may
    exclude the issue you're looking for.
  </Accordion>
  <Accordion title="Why does an issue say its view can't be applied?">
    An issue created in the viewer before 2026.9 can show **Legacy issue — its view can't be applied
    here yet**. Its details and replies still open.
  </Accordion>
</AccordionGroup>

### Issues page in the project

<Frame>
  <img src="/images/3d-viewer/issues-tab.png" alt="Issues tab" />
</Frame>

Open **Issues** in the project sidebar to see issues across all models in the project. Filter the
list by status, priority, assignee, labels, model, or overdue. Select an issue to see its fields,
preview, and replies, or select **Open in viewer** to go to the stored view.

<AccordionGroup>
  <Accordion title="What's the difference between the Issues panel and the Issues page?">
    The **Issues** panel in the viewer shows issues for the models currently loaded. The project's
    **Issues** page shows all issues across all models in the project.
  </Accordion>
  <Accordion title="Can I export the issues list?">
    Not directly. Use the Issues widgets in Intelligence dashboards to build reports of your issues.
  </Accordion>
</AccordionGroup>

### Issues in connectors

Issues are accessible directly in your desktop applications through Speckle connectors for Revit,
Rhino, SketchUp, Navisworks, and other supported applications.

When you load a model in a connector, you'll see an issue icon with the count of open issues. Click
it to view the full list of issues for that model, complete with all properties like labels,
priority, and assignees.

Click any issue to see the associated object highlighted in your host application. This lets you
address problems without switching between your desktop app and the web interface.

<Note>
  Connectors currently show highlighted objects but do not automatically move the camera to focus on
  them. You may need to navigate manually to see highlighted geometry.
</Note>

<AccordionGroup>
  <Accordion title="Can I create issues from the connector?">
    Not yet. Creating issues is available only in the web app.
  </Accordion>
  <Accordion title="Can I reply to issues from the connector?">
    Not yet. Replying is available only in the web app.
  </Accordion>
  <Accordion title="Can I resolve an issue from the connector?">
    Not yet. Changing the status, or any other field, is available only in the web app.
  </Accordion>
  <Accordion title="Will issues update in real-time in my desktop app?">
    No. You'll need to refresh the connector to see the latest issues.
  </Accordion>
</AccordionGroup>

## Issues and model versions

An issue stores the models that were in the scene when you raised it, including a specific version if
you were viewing one. Opening the issue from **Issues** loads those models. If you raised it on an
earlier version, that version loads, so you see the model as it was when the problem was found. If
the version cannot load, the viewer shows **Couldn't load the version this issue was created on**.

<AccordionGroup>
  <Accordion title="What if the object an issue references was deleted in later versions?">
    The issue remains accessible, but the object won't be visible in newer versions. Open the issue
    on the version it was raised on to see the object as it was.
  </Accordion>
  <Accordion title="Should I resolve issues when I publish a new version with fixes?">
    It depends on your workflow. Some teams resolve issues after publishing fixes. Others set them
    to **Ready for Review** and wait for verification before marking them **Resolved**.
  </Accordion>
</AccordionGroup>

## Notifications

You receive email notifications when:

- An issue is assigned to you
- Someone replies to an issue you created, are assigned to, or have replied to

## Permissions

Issue permissions depend on your project role and whether you created or are assigned to a specific
issue.

|                                               | Viewer                 | Editor                 | Owner | Signed-in users on a public project |
| --------------------------------------------- | ---------------------- | ---------------------- | ----- | ----------------------------------- |
| **View issues**                               | Yes                    | Yes                    | Yes   | Yes                                 |
| **Create issues and reply**                   | Yes                    | Yes                    | Yes   | No                                  |
| **Change status, priority, due date, labels** | If creator or assignee | If creator or assignee | Yes   | No                                  |
| **Change assignee**                           | If creator             | If creator             | Yes   | No                                  |
| **Get assigned an issue**                     | Yes                    | Yes                    | Yes   | No                                  |
| **Delete issues**                             | If creator             | If creator             | Yes   | No                                  |
| **Edit replies**                              | No                     | No                     | No    | No                                  |

### Important notes

- Nobody can edit replies after posting, including project owners.
- You must be signed in and have a project role to create issues or reply, even on a public project.
- An assignee can change every field except the assignee.

## If an issue action is blocked

Check these conditions:

- Cannot create an issue or reply -> confirm you are signed in and have the **Viewer** role or higher
  on the project.
- Cannot change a field -> only the issue's creator, its assignee, or a project owner can.
- Cannot set priority, assignee, due date, or labels -> the project must belong to a workspace.
- Cannot see an expected issue -> check filters and include **Resolved** if needed.
- Cannot assign a user -> confirm the user has access to that project.

<AccordionGroup>
  <Accordion title="Why can't I edit someone else's issue?">
    You can change only issues you created or are assigned to. This prevents accidental changes to
    issues you're not working on. Project owners can change all issues.
  </Accordion>
  <Accordion title="Can I remove myself as an assignee?">
    No. An assignee can change every field except the assignee. Ask the issue's creator or a project
    owner to reassign it.
  </Accordion>
  <Accordion title="Why can't I edit my own reply?">
    Replies cannot be edited by anyone once posted. This keeps a clear record of the conversation.
    If you need to correct or clarify something, add a new reply.
  </Accordion>
</AccordionGroup>

## Availability

Issues are available on every Speckle plan, including Free, on Speckle Cloud and on self-hosted
servers. Priority, assignee, due date, and labels need the project to belong to a workspace.
