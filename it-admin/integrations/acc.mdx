Until your organisation enables the Speckle integration on its ACC hub, users cannot sign in to Autodesk from Speckle or create syncs. An IT administrator, or anyone with **Account Admin** access, adds it once for the whole hub.

<Note>
  **Autodesk Forma Data Management** is the current name for **Autodesk Construction Cloud (ACC)**.
  Labels and URLs in Autodesk admin may still use ACC naming.
</Note>

<Note>
  Syncing from Forma Data Management is available on the **Enterprise** plan. See the [user
  guide](/connectors/cloud-integrations/acc) for plan details.
</Note>

<Note>
  On self-hosted deployments, ACC integration is available only on Speckle Enterprise Server with a
  [license key](/developers/server/deployment/enterprise-license#license-key), and your server admin
  turns it on in the deployment first. See [ACC
  integration](/developers/server/deployment/enterprise-license#optional-acc-integration) in the
  Enterprise deployment guide.
</Note>

<Info>
  If **Custom Integrations** is not visible in the Account Admin panel, the account may not have the
  required role. Contact your Autodesk administrator.
</Info>

<Steps>
  <Step title="Add a custom integration in Autodesk admin">
    1. Go to [Autodesk Account Admin](https://acc.autodesk.com/), or [acc.autodesk.eu](https://acc.autodesk.eu/) for the European region. The URL still uses the ACC name.
    2. In the Account Admin panel, select **Custom Integrations**.
    3. Select **Add custom integrations**.
    4. Enter the integration details (copy the Client ID exactly, with no extra spaces):
       - **Client ID**: `5Y2LzxsL3usaD1xAMyElBY8mcN6XKyfHfulZDV3up0jfhN5Y`
       - **Name**: `Speckle`

       <Frame>
         <img src="/images/connectors/cloud-integrations/acc/acc-add custom integration.png" alt="Add custom integration in Autodesk admin" />
       </Frame>
    5. Select **Next**.
    6. On the permission warning, select **Proceed Anyway**.

       <Frame>
         <img src="/images/connectors/cloud-integrations/acc/acc-premission warning.png" alt="Autodesk custom integration permission warning" />
       </Frame>

  </Step>
</Steps>

<Note>
  **The warning in step 6 comes from Autodesk, not Speckle.** Autodesk does not offer granular
  permission controls for Custom Integrations, so the dialog cannot show the actual scope. To sync
  files, Speckle requests only read-only scopes (`account:read`, `user-profile:read`, `data:read`,
  `data:search`, `bucket:read`, `viewables:read`, `openid`). The account a workspace admin connects
  for [issue sync](#connect-an-account-for-issue-sync) also gets `data:write`, so Speckle can write
  ACC issues. See [Autodesk scope
  definitions](https://aps.autodesk.com/en/docs/oauth/v2/developers_guide/scopes/) for details.
</Note>

<Note>
  **To sync files, Speckle inherits each user's existing permissions in Autodesk Forma Data
  Management (ACC).** Users can see only hubs, projects, and folders they already have access to in
  Autodesk. Issue sync works differently: it acts as one connected account for the whole workspace.
</Note>

<Tip>
  For tighter control, create a dedicated Autodesk account with limited access to selected projects
  or folders and use it for Speckle syncs.
</Tip>

After this is enabled, users can continue with [Autodesk Forma Data Management (ACC) user setup](/connectors/cloud-integrations/acc).

## Connect an account for issue sync

[ACC issue sync](/connectors/cloud-integrations/acc-issue-sync) brings the ACC issues pinned to a synced file into Speckle and sends Speckle issues to ACC. It needs the custom integration above, plus one Autodesk account that a workspace admin connects for the whole workspace. It is part of the integration on the **Enterprise** plan.

Speckle reads and writes ACC issues for every project in the workspace as this one Autodesk account. This changes who decides what reaches ACC:

- **Speckle's issue permissions decide, not each person's ACC role.** Anyone who can change an issue's status in Speckle can send it to ACC, unlink it, and change its status there, even without an ACC account.
- **Every write appears in ACC as the connected user.** Speckle names the Speckle person in a footer on sent issues and in a comment on each status change.
- **Imported issues are visible to everyone who can view the Speckle project**, whatever their ACC permissions.
- **The account needs Manage issues** in each ACC project whose files have issue sync on. Turning issue sync on for a sync checks this first. Project Admin is not needed.

<Steps>
  <Step title="Choose the account">
    Use a dedicated Autodesk account with Manage issues only in the ACC projects you want to sync.
    Access then belongs to the role, not to a person who may leave.
  </Step>
  <Step title="Connect it in Speckle">
    As a workspace admin, open **Workspace settings** → **Autodesk ACC**, select **Connect ACC**,
    and sign in to Autodesk with that account in the same browser. You should see the account, who
    connected it, and when.
  </Step>
  <Step title="Check which syncs use it">
    **Used by** lists the syncs with issue sync on. These are what disconnecting or replacing the
    account affects.
  </Step>
</Steps>

Speckle keeps the connection alive while nobody uses it. If the account stops working, for example because its sign-in was revoked or it lost access, issue sync pauses in both directions on every sync in the workspace, and every workspace admin gets one email. Select **Reconnect** to resume: each linked issue then catches up with ACC, with nothing to reconfigure. **Change account** replaces the account; **Disconnect** pauses issue sync without an email until an admin connects an account again.

<Warning>
  Disconnecting pauses issue sync on every sync listed in **Used by**. Replacing the account changes
  who later ACC writes appear as, and the new account needs Manage issues in the same ACC projects.
</Warning>
