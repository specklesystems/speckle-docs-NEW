## 2026.9 dates and actions

2026.9 moves Speckle to a new data model. It does not change how you install connectors, configure
SSO, or enable ACC and ProjectWise. Two dated actions apply to your organization:

| Date            | What you do                                                                                                                               | Learn more                                                                         |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Now             | Roll connector updates across the estate. The upgrade window opened on 1 September 2026.                                                  | [Upgrade window for 2026.9](/it-admin/connector-updates#upgrade-window-for-2026-9) |
| Now             | If ACC sync or file uploads feed a tool that still needs the earlier data format, ask Speckle for compatibility mode and update the tool. | [Compatibility mode](/it-admin/compatibility-mode)                                 |
| 1 November 2026 | Compatibility mode ends for every workspace. Finish connector updates.                                                                    | [What's new for IT admins](/whats-new/it-admins)                                   |

Speckle does not guarantee that connectors from 2026.8 or earlier keep working after the window
closes, so upgrade. Models already published stay readable. Compatibility mode applies only to
cloud syncs and file uploads, not to desktop connectors. For the summary for workspace members, see [Speckle's
new data model](/workspaces/data-model-migration).

<Note>
  On a self-hosted server running a release before 2026.9, these dates and steps differ. See
  [Compatibility mode](/it-admin/compatibility-mode#self-hosted-servers).
</Note>

## Connector installation

Speckle connectors enable users to publish and load data from design applications like Revit, Rhino, and Archicad.

Connector updates work in two parts:

- **Desktop UI (DUI)**: Updated centrally and automatically propagates to all connectors without requiring connector updates. This shared interface handles authentication and common workflows.
- **Connector addons**: Updated separately for each connector. Each application-specific connector (Revit, Rhino, etc.) must be updated individually.

When deploying connectors manually, you only need to update connector addons. DUI updates automatically.

<Note>
  To turn off update notifications, set `SPECKLE_IS_UPDATE_NOTIFICATION_DISABLED`. See [Connector
  Configuration](/connectors/connector-configuration).
</Note>

Speckle connectors are updated frequently to stay compatible with the continuously updated Speckle server. Connectors are open source and can be inspected for security and compliance. If your organization requires approval for every software update, factor this frequent update cadence into your deployment process: consider a faster approval workflow or allowing automatic updates for patch releases.

<Note>
  The Speckle server is also open source with delayed releases, so you can inspect changes before
  deployment if you run a self-hosted instance.
</Note>

### Standard installation

Users can download and install connectors directly from [app.speckle.systems/connectors](https://app.speckle.systems/connectors). Standard installers handle dependencies automatically and are recommended for most deployments.

[View Standard Installation Guide](/connectors/installation)

### Manual installation

For environments that restrict executable installers or require centralized deployment, use manual ZIP-based installation:

- **Download ZIP files:** <a href="https://releases.speckle.systems/" rel="nofollow">releases.speckle.systems</a>
- **Installation instructions:** [Manual Installation Guide](/connectors/manual-installation/introduction)

The manual installation guide includes step-by-step instructions for all supported connectors. Current connector versions do not need the [Desktop Services](/connectors/manual-installation/desktop-services) background service; the manual installation pages state which older versions did.

## Cloud integrations

Before enabling any integration, read [Cloud Integrations: Access and Governance](/it-admin/integrations/introduction) — it explains which identity each integration acts as and where the access boundary is set.

### Autodesk Forma Data Management (ACC)

Setup is user-led after the integration is enabled. **IT Administrators** enable the Speckle integration on the **ACC Hub** (Autodesk Forma Data Management admin). Once enabled, users connect from a project's **Integrations** → **ACC** page and follow the [Forma Data Management integration guide](/connectors/cloud-integrations/acc) for project syncing.

[Enable Autodesk Forma Data Management integration](/it-admin/integrations/acc)

### Bentley ProjectWise

Speckle supports two ProjectWise connections:

- **Cloud** uses Bentley IMS. Add the Speckle service account to each Bentley project users need to sync.
- **On-Prem** connects directly to WSG v2.9. Enable Native Authentication and make the WSG endpoint reachable from the Speckle backend.

Users complete the connection from their Speckle project after IT prepares the selected environment.

[Configure Bentley ProjectWise integration](/it-admin/integrations/projectwise)

<Note>
  ProjectWise updates are detected by scheduled checks. The integration is read-only and focuses on
  model and file synchronization rather than general document management.
</Note>

### Trimble Connect

Trimble Connect has no hub-level enablement step. A workspace admin connects a dedicated Trimble
**service account** from a project's **Integrations** → **Trimble Connect** page, and invites that
account to every Trimble Connect project users need to sync.

[Sync models from Trimble Connect](/connectors/cloud-integrations/trimble-connect)

### SharePoint

A Microsoft admin approves Speckle's app once for your Microsoft 365 organization. Until then,
nobody in the organization can sign in to SharePoint from Speckle. After the approval, members
connect from a project's **Integrations** → **SharePoint** page.

[Approve Speckle for SharePoint](/it-admin/integrations/sharepoint)

## Single sign-on (SSO)

Configure SSO to allow users to access Speckle using your organization's existing identity provider. Speckle supports any OIDC identity provider.

<Note>SSO is available on the Enterprise plan.</Note>

[View SSO Setup Guide](/workspaces/sso)

The SSO setup guide includes the redirect URL, required scopes, grant type configuration, and identity provider setup steps.

## Turn AI features off for the workspace

A workspace admin can turn
**AI features** off for the whole workspace from workspace **Settings**, then **General**. Members
and guests can open the General page but cannot change the switch.

{/* IMAGE_PLACEHOLDER: Workspace Settings → General with the AI features switch turned off. */}

When AI features are off, **Chat** and the sparkle control in the 3D viewer are unavailable to
everyone in the workspace, so nobody can start a conversation or spend AI credit. Turn the switch
back on the same way to restore access.

The switch is a workspace setting. If your organization runs several workspaces, turn AI features
off in each one.

### Enterprise controls for AI

On the Enterprise and Unlimited plans, the AI card in **Settings**, then **General**, also shows
an **Enterprise controls** section with two checkboxes. Both are off by default. Only workspace
admins can change them. Members see the controls but cannot change them, and on other plans the
controls are disabled.

- **Only workspace admins can enable AI**: members can no longer accept the AI terms for the
  workspace. A member who tries sees a **Contact your workspace admin** dialog that says "A
  workspace admin must enable AI for this workspace". An admin then enables AI for the workspace.
- **Disable public sharing of AI conversations**: nobody can create a new public link to an AI
  conversation, and existing public links stop working at once. Members can still share a
  conversation with signed-in project members.

If the workspace moves to a lower plan, the values you set stay in force, but you cannot change
them until the workspace is back on Enterprise or Unlimited.

<Note>
  On a self-hosted Speckle Enterprise Server, your server administrator turns on Intelligence and
  connects it to your organisation's AI provider. See [Enable
  Intelligence](/developers/server/deployment/enterprise-license#enable-intelligence).
</Note>

For the rest of workspace Settings, see [Configuration](/workspaces/configuration#workspace-settings).
For activity, plan limits, and AI spend, see [Usage statistics](/workspaces/usage). Organization
playbooks for Intelligence are [skills](/analytics/intelligence-skills), and standing constraints on
every conversation are [AI Rules](/analytics/intelligence-rules).

## Firewall and network requirements

Speckle requires outbound HTTPS connections to function. Allowlist the following domains and URLs to allow connectors, the web application, and API access.

### Required domains

Allow outbound HTTPS (port 443) connections to:

<Tip>
  For simplified firewall configuration, you can allowlist `*.speckle.systems` and `*.speckle.dev`
  to cover all Speckle domains. This includes current and future subdomains.
</Tip>

| Domain                       | Purpose                                   | Required For                        |
| ---------------------------- | ----------------------------------------- | ----------------------------------- |
| `app.speckle.systems`        | Main API, web application, authentication | All functionality                   |
| `dashboards.speckle.systems` | Intelligence dashboards                   | Analytics and dashboards (optional) |
| `docs.speckle.systems`       | Documentation                             | Reference access (optional)         |
| `dui.speckle.systems`        | Desktop UI updates and components         | Connector functionality             |
| `releases.speckle.systems`   | Manual connector ZIP downloads            | Manual installation                 |
| `releases.speckle.dev`       | Connector feed data                       | Connector update checks             |
| `speckle.community`          | Support forum, community resources        | Support access (optional)           |
| `www.speckle.systems`        | Connector downloads, documentation        | Connector installation              |
| `*.digitaloceanspaces.com`   | File storage and uploads                  | Publishing, loading, file uploads   |

<Note>
  The `dashboards.speckle.systems` domain is hosted on Netlify infrastructure during beta. If you
  encounter connectivity issues, contact [support@speckle.systems](mailto:support@speckle.systems)
  for current hosting details.
</Note>

### API endpoints

The following endpoints must be accessible for full functionality:

GraphQL API:

- `https://app.speckle.systems/graphql`

REST API:

- `https://app.speckle.systems/api/v1/*`

Authentication:

- `https://app.speckle.systems/api/v1/auth/*`
- `https://app.speckle.systems/api/v1/workspaces/*/sso/oidc/callback` (for SSO)

WebSocket (for real-time features):

- Allow WebSocket connections (WSS) to `app.speckle.systems` for real-time features in the web application

File storage:

- Publishing and loading models, and file uploads, use presigned URLs on `*.digitaloceanspaces.com` (for example `ams3.digitaloceanspaces.com`). Connectors and browsers connect to these hosts directly, not through `app.speckle.systems`. If you encounter issues, ensure `app.speckle.systems` and `*.digitaloceanspaces.com` are fully allowlisted.
- If your network inspects or re-signs HTTPS traffic (TLS/SSL inspection, common with VPNs and secure web gateways), exclude these domains from inspection. Allowlisting alone is not enough. The usual symptom is that a connector signs in and lists projects, but publishing or loading fails with `certificate verify failed`.

### Self-hosted servers

If your organization uses a self-hosted Speckle server, replace `app.speckle.systems` with your server's domain in all URLs above. Ensure your server domain is allowlisted and accessible from user workstations.

<Info>
  For self-hosted deployments, see the [Server Deployment Guide](/developers/server/getting-started)
  for infrastructure requirements.
</Info>

### Port requirements

- **Outbound HTTPS:** Port 443 (required)
- **Outbound HTTP:** Port 80 (optional, for redirects only)
- **WebSocket:** Port 443 (WSS, required for real-time features)

### Regional considerations

`app.speckle.systems` is served through Cloudflare, which uses a global CDN with dynamic IP addresses that change frequently. For this reason, domain-based firewall rules are strongly recommended over IP-based rules.

If your organization requires IP-based firewall rules, you can refer to [Cloudflare's published IP ranges](https://www.cloudflare.com/ips/). However, these ranges are large and change regularly, making domain-based rules more reliable and easier to maintain.

<Info>
  For the most current IP ranges or assistance with firewall configuration, contact
  [support@speckle.systems](mailto:support@speckle.systems).
</Info>

<Note>
  For organizations with strict egress controls, consider deploying a self-hosted Speckle server to
  keep all traffic within your network.
</Note>

## Email deliverability: IP allowlisting

To ensure reliable delivery of system emails (notifications, alerts, reports, etc.), customers with strict email security policies may need to allowlist the IP ranges used by our email delivery provider.

If your organization uses email gateways, spam filters, or firewall rules that restrict incoming email traffic, add the following IP ranges to your allowlist.

### Sending IP ranges

- `205.201.128.0/20`
- `198.2.128.0/18`
- `148.105.0.0/16`

### What this means

These CIDR ranges are used by our email service provider to send outbound messages. Allowlisting them helps ensure that messages from our platform are not blocked or quarantined by your email security infrastructure.

### Who should configure this

This is typically configured by your:

- Email administrators
- IT or security team
- Network or firewall administrators

### Where to add the allowlist

Depending on your environment, the IP ranges may need to be added to:

- Email security gateways (e.g., Proofpoint, Mimecast, Barracuda)
- Spam filtering systems
- Microsoft 365 / Exchange mail flow rules
- Google Workspace allowlists
- Network firewalls or secure email gateways

<Tip>
  Add these ranges to your trusted sender or inbound allowlist policies to prevent email filtering
  or blocking.
</Tip>

<Note>
  These IP ranges are maintained by our email provider and may change periodically. If your
  organization requires domain-based allowlisting instead, contact
  [support@speckle.systems](mailto:support@speckle.systems).
</Note>

  <Accordion title="Is the in-app support chat AI or human?">
    Both. The in-app chat is powered by Intercom FinAI for first-line responses.
    It is informed by Speckle documentation, previous support interactions, and
    public open-source repositories. Human support engineers review, follow up,
    and handle complex or escalated cases.
  </Accordion>

<Accordion title="Why are connectors blocked even though ports are open?">
  Some firewalls require separate configuration to allow non-browser applications to access domains.
  Even when ports 443 and 80 are open, firewall rules may block applications like connectors that
  aren't web browsers. Configure your firewall to allow outbound HTTPS connections from all
  applications, not just browsers, or create specific rules for the connector executables.
</Accordion>

<Accordion title="Do connectors work behind a corporate proxy?">
  Connectors support HTTP proxies configured at the system level. Ensure proxy settings allow HTTPS
  connections to `app.speckle.systems`. Authentication may require interactive browser sessions.
</Accordion>

<Accordion title="What if we block WebSocket connections?">
  WebSocket connections are used for real-time features in the web application, and the Speckle 3D
  visual for Power BI streams geometry over a WebSocket. Connectors will function without WebSocket
  access, but some web app features may be limited and the Power BI 3D visual cannot load geometry.
</Accordion>

  <Accordion title="Can we deploy connectors without internet access?">
    No. Connectors require internet access to authenticate users and transfer
    data. For air-gapped environments, deploy a self-hosted Speckle server
    within your network.
  </Accordion>
</AccordionGroup>
