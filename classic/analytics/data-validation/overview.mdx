<Info>

## Validation options in Classic

Classic data validation centers on Intelligence dashboard widgets:

- **Property Checker**: ad-hoc, single-property spot checks
- **Model Validation**: ruleset-based validation for one model

Both are configured and consumed in dashboards.

## Product maturity path

Classic Model Validation widgets remain documented for existing dashboard
workflows. The product maturity path now points to **Data Validation (checks and
standards)** in the web app.

Use [Data Validation Overview](/analytics/data-validation/overview) when you need
persistent check execution, standards reuse, and detailed run history.

## Typical Classic workflow

<Steps>
  <Step title="Open Intelligence dashboard">
    Create or open a dashboard with model data sources.
  </Step>
  <Step title="Add validation widget">
    Add Property Checker for quick checks or Model Validation for full rulesets.
  </Step>
  <Step title="Define rules">
    Configure `WHERE` / `AND` / `CHECK` conditions and severity.
  </Step>
  <Step title="Run and interpret">
    Review pass/fail outcomes in widget views and 3D viewer colorization.
  </Step>
</Steps>

## Migration context

Legacy/internal terms often map like this:

- `ruleset` remains common in Classic widget language
- `insight` may appear in technical references

For user-facing guidance in checks-and-standards Data Validation, these map to
**standard** and **check**.
