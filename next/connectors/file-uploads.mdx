Check your workspace’s upload mode before uploading a file in 2026.9. Some formats require
legacy/compatibility mode, which ends on **1 November 2026**. Tekla Structures uploads are available
where enabled.

## Breaking change: supported file formats

<Warning>
  In 2026.9, the default file upload path no longer accepts **STL**, **3MF**, **3DS**, **AMF**,
  **DXF**, **X**, **E57**, **IGS/IGES**, **FBX**, **PLY**, or **SLDPRT**. Earlier upload-format
  lists do not apply to this path. **These formats remain supported for direct uploads in
  legacy/compatibility mode only until it ends on 1 November 2026.** Move affected workflows to a
  supported format before then.
</Warning>

This affects both drag-and-drop uploads in the web app and uploads through the API. Existing
models stay readable; the change affects importing new files and uploading new versions.

## Additional format: Tekla Structures

2026.9 adds support for Tekla Structures model packages (`.tekla`) and model databases (`.db1`)
on deployments where Tekla uploads are enabled. This is not enabled by default; confirm
availability with Speckle before relying on it for your workflow.

Use the complete model folder when uploading a Tekla model to preserve profiles, shapes, and materials.

<Tip>
  A `.tekla` package contains the model folder and its supporting catalogs. A `.db1` file alone can
  be converted, but missing catalogs can reduce profile, shape, and material fidelity.
</Tip>

## Upload a Vectorworks file

If your design lives in Vectorworks, you can upload the `.vwx` file to publish it without opening
Vectorworks or installing its connector. For the steps, see
[Upload a file](/connectors/direct-uploads/introduction#upload-a-file). The
[Vectorworks connector](/connectors/third-party/vectorworks) publishes the objects you select; an
upload publishes the 3D content of every design layer.

### Files that convert

Speckle reads files last saved in Vectorworks 2021 through 2027. Files from other releases are not
supported yet.

### What is published

- 3D objects on every design layer, including design layers hidden in the document, grouped by
  story, layer, and type.
- Each object's name, type, object properties, and IFC properties. An object whose 3D geometry
  Speckle cannot read arrives with its properties and no geometry.

These parts of the document are not published:

- Objects in a class that is hidden in the document.
- Sheet layers.
- 2D-only objects, such as callouts, data tags, and section lines.

<Note>
  Speckle follows the class visibility saved in the file. To include a hidden class, make it visible
  and save the file before you upload it.
</Note>

### If a Vectorworks upload fails

| Message                                                  | What to do                                                                         |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Vectorworks file version _number_ is not supported       | Contact Speckle support.                                                           |
| This is not a supported Vectorworks document             | Check that the file is a Vectorworks document, not another file renamed to `.vwx`. |
| This Vectorworks document uses an unsupported byte order | Contact Speckle support.                                                           |

## Upload a Solibri file

Upload a Solibri `.smc` file to publish the whole federation saved in it, without opening Solibri
or installing a connector. You do not need the original IFC files alongside it. For the steps, see
[Upload a file](/connectors/direct-uploads/introduction#upload-a-file). After conversion, open the
model in Speckle to view its geometry and inspect its properties.

### Files that convert

Files saved in Solibri 9.12 and 26.6 have been verified. Speckle attempts to read `.smc` files from
other releases, but their compatibility has not been verified. `.smv` and `.smct` files are not
supported.

### What is published

- The saved federation, grouped by source model and its spatial hierarchy.
- Component geometry with original colours and transparency.
- Source properties, Solibri-derived properties, and saved classification results, including
  group, zone and system memberships.

These parts of the document are not published:

- Rule sets and checking results.
- Presentations.
- Issues and BCF data.

An upload reads the data saved in the file; it does not run Solibri checks or re-evaluate
classifications.

<Note>
  Solibri uploads require the default 2026.9 upload mode. Workspaces using legacy/compatibility mode
  cannot upload `.smc` files.
</Note>

### Recover missing Solibri geometry

For the closest match to Solibri's 3D view, save the file with **Save 3D Representations with Model**
enabled under **Settings > 3D** in Solibri. Let the 3D view finish drawing before saving.

When the file has no saved 3D representation for a component, Speckle tries to rebuild its geometry.
This takes longer and can produce approximate geometry. Components that cannot be rebuilt retain
their properties but have no geometry. Open the file in Solibri, enable the setting, let the 3D
view draw, save and upload it again.

### Recover a missing Federated Floor property

A component's **Federated Floor** property is included only if Solibri computed and saved it.
To populate it, open the file in Solibri, group the model tree by **Locations**, and use
**Save As** before uploading again. Some components may still have no federated floor.

### If a Solibri upload fails

If the upload fails, check that the file opens in Solibri and save it again before retrying. Contact
Speckle support if it still fails.

## Upload an ETABS model

Upload an ETABS `.edb` file to publish the model without opening ETABS or installing its connector.
Add the result files ETABS saves beside it to publish the analysis results too. For the steps, see
[Upload a file](/connectors/direct-uploads/introduction#upload-a-file). An upload publishes the
whole model, with the same objects and properties as the [ETABS connector](/connectors/etabs).

### Files that convert

Speckle reads files saved in ETABS 18 through 23.0. Files from other releases are not supported
yet. Analysis results from ETABS 18 files are not supported.

These limits apply to an ETABS upload:

- Each file, including the `.edb`, can be up to 128 MiB.
- The `.edb` and its result files together can be up to 640 MiB.
- An upload can include up to 100 result files.

### Add the analysis results

The `.edb` holds the model, not its analysis results. ETABS saves the results beside it in result
files with the same name as the model: a `.msh` file and `.Y` files, such as `.Y`, `.Y00`, `.Y01`,
`.Y$$`, `.Y_` or `.Y_1`. Upper and lower case in file names do not matter.

To upload a model with its results, do one of the following:

- Drop the model folder, or select the `.edb` together with its result files. The upload starts
  immediately.
- Drop the `.edb` on its own. In **Add the analysis results**, drop the model folder or the result
  files, or use **Choose folder** or **Choose files**. Then select **Upload with results**.

A folder that holds the `.edb` but no result files also opens **Add the analysis results**. To
publish the model without results, select **Upload model only**.

Result files must be in the same folder as the `.edb`. Speckle leaves out files in subfolders and
files that do not match the model, and does not upload them.

<Note>
  If a result file the analysis needs is missing, the model publishes without any analysis results.
  The upload does not report an error. Upload every result file ETABS saved for the model.
</Note>

### What is published

- Joints, frames, tendons, shells and links, with their geometry, grouped by level.
- Each object's type and properties, such as its section, material, length or area.
- Section and material definitions.
- Analysis results, when you upload the result files. As with the connector, they are stored on the
  model, not on each object. To find them, see the
  [ETABS connector FAQ](/connectors/etabs#publishing-a-model).

An upload reads the data saved in the files. It does not open ETABS, rerun the analysis or
recalculate the design.

### If an ETABS upload fails

| Message                                                                                            | What to do                                                                                                                                        |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| "_name_" exceeds the ETABS limit of 128 MiB per file.                                              | If it is a result file, drop the `.edb` alone and select **Upload model only**. Otherwise, publish with the [ETABS connector](/connectors/etabs). |
| This model and its result files exceed 640 MiB. Select a smaller model file set.                   | Drop the `.edb` alone and select **Upload model only**, or publish with the [ETABS connector](/connectors/etabs).                                 |
| This selection has more than 100 result files. Select only the EDB and its result files.           | Select only the `.edb` and the result files that share its name.                                                                                  |
| This selection contains multiple EDBs. Drop the .edb you want and add its results from the dialog. | Upload one model at a time. Drop its `.edb` and add its result files in the dialog.                                                               |
| Duplicate ETABS filename: "_name_". Remove files that differ only in case.                         | Keep one copy of each file.                                                                                                                       |
| No result files for "_model_" were found.                                                          | Choose the folder that holds the `.edb`, or result files with the same name as the model.                                                         |
| No result files for "_model_". This selection contains "_other model_".                            | Choose the folder or result files of the model you are uploading.                                                                                 |

If the upload fails after it starts, check that the file opens in ETABS before retrying. Contact
Speckle support if it still fails.

## Upload an AVEVA Review model

Upload an AVEVA Review `.rvm` file to publish a plant model from AVEVA E3D or PDMS without
installing a connector. Add the attribute export and the DEXPI P&IDs to publish the model's
properties and its pipeline systems too. For the steps, see
[Upload a file](/connectors/direct-uploads/introduction#upload-a-file).

### Files that convert

| File               | Extension      | What it adds                                                            |
| ------------------ | -------------- | ----------------------------------------------------------------------- |
| Review model       | `.rvm`         | Geometry, colours and the model tree. Required.                         |
| Attribute export   | `.txt`, `.att` | Names, types and attributes of each element. Optional, at most one.     |
| DEXPI P&ID exports | `.xml`         | Pipeline systems, flow connections and P&ID tags. Optional, any number. |

Speckle reads binary RVM files. ASCII RVM files are not supported. The attribute export is the
`CADC_Attributes_File` text file AVEVA writes beside the RVM, usually with the same name.

### Add the attribute export and P&IDs

Drop the `.rvm` on its own, or together with its attribute export and P&IDs. Speckle then asks
for the companion files in two dialogs. Files you dropped together with the `.rvm` are already
added.

<Steps>
  <Step title="Add the attribute export">
    In **Add the attribute export**, drop the `.txt` or `.att` file and select **Continue**. To
    publish geometry only, select **Upload without attributes**.
  </Step>
  <Step title="Add the P&IDs">
    In **Add P&IDs**, drop the DEXPI `.xml` exports and select **Upload with _n_ P&IDs**. To publish
    without them, select **Upload without P&IDs**.
  </Step>
</Steps>

The upload starts, and the model appears in your project once it converts.

Speckle checks each file before the upload. A check never blocks the upload: a file with a
warning is still uploaded.

| Badge            | Meaning                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------- |
| Attribute export | The file is an attribute export of this model.                                            |
| Other model      | The attribute export belongs to another model. The dialog names both.                     |
| Cited            | The attribute export cites this P&ID's drawing number.                                    |
| Not cited        | The attribute export does not cite this drawing. Its items can still match by tag.        |
| Not recognised   | The file is not an attribute export or a DEXPI export. A P&ID with this badge is skipped. |
| Not checked      | Speckle could not read the file in the browser. It is uploaded unchecked.                 |

When you add an attribute export, **Add P&IDs** lists the drawings it cites, marked **Included**
or **Missing**. Use the list to find missing P&IDs. A drawing number can contain `*`, which file
names cannot, so its file usually has `_` in that place.

<Note>
  Closing either dialog asks first. Select **Upload without attributes** or **Upload without P&IDs**
  to continue without those files, **Cancel upload** to stop without creating anything, or **Go
  back** to return to the dialog.
</Note>

### What is published

- Every element of the model tree, such as sites, zones, equipment and pipes, grouped as in the
  model, with its geometry, colour and transparency. Lengths are in millimetres.
- With the attribute export: each element's name, type and attributes, under **Attributes**.
  Elements the export lists without geometry, such as nozzles outside the exported level range,
  arrive as objects with properties only.
- With P&IDs: each pipeline on the P&IDs becomes a system holding its pipe and the components
  on it. Matched objects get **P&ID** properties, such as tag, drawing number, line number,
  fluid code, nominal diameter and piping class, and are connected in the flow direction the
  P&ID draws.

P&ID items are matched to model objects by tag. Items whose tags are not in the model, such as
fittings and off-page connectors, are not published as objects.

<Tip>
  An attribute export that matches few elements of the model usually belongs to another model.
  Export it again from the same model as the RVM and upload both.
</Tip>

<Note>
  Cloud sync publishes an `.rvm` without its attribute export and P&IDs: geometry, colours and the
  model tree only.
</Note>

### If an AVEVA Review upload fails

If the upload fails, check that the file is a binary RVM export and that it opens in AVEVA
Review or Navisworks before retrying. Contact Speckle support if it still fails.

## Upload GIS data

Upload GIS data to publish map layers in Speckle, without opening a GIS application. Speckle
reads these formats:

| Format                | Upload                                             |
| --------------------- | -------------------------------------------------- |
| GeoPackage            | `.gpkg`                                            |
| GeoJSON               | `.geojson`                                         |
| GeoJSON, line by line | `.geojsonl`                                        |
| KML                   | `.kml`                                             |
| Shapefile             | a zip named `.shp.zip`                             |
| Esri file geodatabase | a zip named `.gdb.zip`                             |
| QGIS project          | `.qgz` or `.qgs`, with a zip of its project folder |

For the steps, see [Upload a file](/connectors/direct-uploads/introduction#upload-a-file). A QGIS
project needs one more step; see [Upload a QGIS project](#upload-a-qgis-project).

### Name zipped shapefiles and geodatabases

A shapefile is several files and a file geodatabase is a folder, so upload each as a zip. The
name tells Speckle what the zip holds:

- Zip the shapefile's files, such as `.shp`, `.shx`, `.dbf`, `.prj` and `.cpg`, and name the zip
  `<name>.shp.zip`. A zip can hold several shapefiles.
- Zip the `.gdb` folder and name the zip `<name>.gdb.zip`.

Speckle does not accept a zip with any other name. The model is named without the double
suffix: `parcels.shp.zip` publishes the model `parcels`.

### Upload a QGIS project

A QGIS project holds the layers, groups and styling of a map, but not the data they show. Upload
it together with a zip of its project folder: the folder that holds the project and every file
its layers use, subfolders included.

<Steps>
  <Step title="Zip the project folder">
    Save the project in QGIS, then zip the folder that holds the `.qgz` or `.qgs` file and its data.
  </Step>
  <Step title="Upload the project">
    Upload the `.qgz` or `.qgs` file. To add the zip in the same step, drop both files together.
  </Step>
  <Step title="Add the project folder">
    In **Add the project folder**, drop the zip. When the badge shows **Project folder**, select
    **Continue**.
  </Step>
</Steps>

If the zip does not contain the project, its badge shows **Project missing** and **Continue**
stays unavailable. Zip the folder that holds the project, not only its data.

<Note>
  A QGIS project converts only together with its project folder, so there is no upload without it.
  Closing the dialog asks whether to **Cancel upload** or **Go back**.
</Note>

The model shows the map as it looks in QGIS:

- Layers keep their legend names, groups and order. The project CRS is the model's coordinate
  system.
- Single-symbol, categorized and graduated styles keep their colours. A rule-based style colours
  the whole layer with its first symbol.
- Layers unchecked in the legend are not published. Layer filters apply.
- Polygon layers with a 3D renderer are extruded as in the QGIS 3D view.

Only file-based vector layers are published. Raster, mesh and point cloud layers, database and
web service layers such as PostGIS, WFS and XYZ tiles, and delimited text and memory layers are
not imported. Labels, symbol sizes, line widths, layer opacity and joins are not published.

<Tip>
  Layers that point at files outside the project folder, such as absolute paths from your computer,
  are found by file name inside the zip. If Speckle still cannot find a layer's data, the layer is
  not published.
</Tip>

### What is published

- Each layer as a collection, and each feature as an object with its fields as properties.
- Points, lines and polygons, including 3D multipatch geometry. Curves are approximated with
  straight segments.
- A colour for each layer. KML features keep the colour of their style.
- Building footprints with a height field, such as a building height, a roof and ground height,
  or a storey count, are extruded to their height. Footprints without a usable height stay flat.
- When a GeoPackage holds the same buildings in several levels of detail, such as `lod12_3d` and
  `lod22_3d` layers, only the highest 3D level of detail is published, with every layer that is
  not a level of detail, such as footprints.

Speckle moves the data close to the model origin and stores its coordinate system and location
on the model. Data in latitude and longitude is projected to a local metric system. Projected
data keeps its units, except US survey feet, which are converted to metres.

These parts of the data are not published:

- KMZ files and KML network links.
- 3D models in KML placemarks. The placemarks arrive with their properties and no geometry.
- Raster data.

### If a GIS upload fails

| Message                                                                                           | What to do                                                                                     |
| ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Unsupported file type. Name a zipped shapefile .shp.zip and a zipped file geodatabase .gdb.zip…   | Rename the zip by its content, or upload the QGIS project first and add the zip in the dialog. |
| '_zip_' does not contain _project_ — zip the folder that contains the project and all of its data | Zip the folder that holds the project file, not only its data.                                 |
| '_zip_' is empty                                                                                  | Zip the project folder again and check that it holds the project and its data.                 |
| encrypted zip entries are not supported                                                           | Zip the folder again without a password.                                                       |

If the upload fails after it starts, check that the file opens in QGIS before retrying. Contact
Speckle support if it still fails.

<Note>
  Cloud sync publishes GIS files the same way, except QGIS projects: a synced project has no project
  folder zip, so its conversion fails. Sync the data files instead.
</Note>

## Update an affected workflow

If your workspace uses legacy/compatibility mode, you can continue uploading the affected
formats until compatibility mode ends on **1 November 2026**. Before moving to the default 2026.9 mode,
export to a supported format or publish through a supported desktop connector. Check the
resulting model before switching your workflow: uploads and connector publishing can produce
different geometry and properties. See [Uploads and connectors produce different
datasets](/connectors/direct-uploads/introduction#uploads-and-connectors-produce-different-datasets).

For the upload steps, see [Upload a file](/connectors/direct-uploads/introduction#upload-a-file).
For programmatic uploads, see [Uploading IFC and other files](/developers/api/guides/file-uploads).
Use the supported formats on this page for 2026.9.

## Temporary compatibility option

Legacy mode, also called compatibility mode, retains direct upload support for the affected
formats when the older conversion service is enabled. Ask Speckle to confirm availability for your workspace. It ends for every workspace on **1 November 2026**. This exception applies
to direct uploads, not cloud sync.

Compatibility mode affects the entire workspace's upload and sync routing; it is not a per-file
fallback. **DGN uploads are not supported in compatibility mode.**

For availability, the **1 November 2026** end date, and how to request it, see
[Compatibility mode for ACC sync and uploads](/next/it-admin/compatibility-mode).
