Use these steps when your report needs to load versions published in the new data format. They
use Power BI connector release **2026.10.0**, which supports both existing `Speckle.GetByUrl`
queries and new `Speckle.GetTables` queries. For the new tables and visual, see
[Power BI in 2026.9](/next/connectors/power-bi/introduction). For legacy workflows and unchanged
setup guidance, see [How to use Speckle for Power BI](/connectors/power-bi/power-bi).

There is no automatic conversion. Renaming the function in the Advanced Editor is not enough.

<Warning>
  From 2026.10.0, the new visual has a separate identity and leaves legacy visuals in place on
  import. Releases 2026.9.0 through 2026.9.2 shared the legacy identity and could replace legacy
  visuals on import. Use 2026.10.0 or later to keep both visuals in a report.
</Warning>

## When to switch

Your report is at risk if all three statements are true:

- It uses `Speckle.GetByUrl`.
- It points to a model URL instead of a specific version.
- The model will be published with a 4.0 authoring connector.

Version 4.0 authoring connectors publish artifact-only versions. The next refresh then fails with
`JsonRepresentationUnavailable`. Pinning to a pre-4.0 version URL is a stopgap. Rebuild the report
if it must keep following new versions.

Reports whose target versions still contain JSON data can keep using `GetByUrl` and the legacy
visual. Updating the connector alone does not require a rebuild.

## Before and after

| Before                                    | After                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| Existing query calls `Speckle.GetByUrl`   | **Connect to Speckle (Custom)** creates a `Speckle.GetTables` query      |
| `Speckle.GetByUrl` returns one flat table | `Speckle.GetTables` returns related tables                               |
| Join and color on `Application ID`        | Join and bind on `Object Key`                                            |
| Legacy 3D visual                          | Separate new visual with **Model Info** and **Object Keys** from Objects |
| JSON-only versions                        | Artifact bundles published with a 4.0 connector                          |

| Version contains                   | `Speckle.GetByUrl`                        | `Speckle.GetTables`                                      |
| ---------------------------------- | ----------------------------------------- | -------------------------------------------------------- |
| JSON and artifacts                 | Returns the legacy flat table             | Returns the new tables                                   |
| JSON only, published before 4.0    | Returns the legacy flat table             | Fails and directs the user to `GetByUrl` or republishing |
| Artifacts only, published with 4.0 | Fails and directs the user to `GetTables` | Returns the new tables                                   |

## How to switch

### Pin a broken report

If the report already fails, pin it to the last version published before 4.0.

<Steps>
  <Step title="Open the GetByUrl query">
    Open Power Query and select the query that calls `Speckle.GetByUrl`. You should see the model
    URL in the formula.
  </Step>
  <Step title="Pin the URL to a version">
    Change the model URL to `.../models/MODEL_ID@VERSION_ID` for the last version that still
    contains JSON. You should be able to refresh against that version again.
  </Step>
</Steps>

<Note>
  After you pin the URL, the report no longer follows new publishes. Continue the steps below when
  the report must pick up new versions.
</Note>

### Rebuild the queries

Use the existing model URL. Do not rename `GetByUrl` to `GetTables` in the Advanced Editor.

{/* IMAGE_PLACEHOLDER: Model view — one-to-one relationship from Properties and Relations to Objects on Object Key. */}

<Steps>
  <Step title="Connect to Speckle">
    Select **Get Data**, search for Speckle, then select **Connect to Speckle (Custom)** and
    **Connect**. Paste the existing model URL in **Speckle Model URL** and sign in when prompted.
    You should see Objects, Properties, and Relations in Navigator.
  </Step>
  <Step title="Load Objects">
    Select **Transform Data** and enable load for Objects. You should see one row per object, with
    `Object Key`, `Application ID`, and `Model Info`.
  </Step>
  <Step title="Choose properties and related fields">
    Select the Properties function, choose the columns used by the report, and invoke it to create a
    new query. Do the same with Relations for fields such as levels or rooms. Enable load for the
    resulting tables and leave the function queries with load disabled. After **Close & Apply**,
    create one-to-one relationships from the resulting tables to Objects using `Object Key`.
  </Step>
</Steps>

For Navigator layouts, column naming, and M helpers, see [Power BI in
2026.9](/next/connectors/power-bi/introduction).

### Reconnect charts, measures, and slicers

Update every report element that references the old table. Check column names. Shortened property
paths, numeric collision suffixes, and the `Type_` prefix may change table references and
calculations.

### Add the new 3D visual

{/* IMAGE_PLACEHOLDER: Report page — new Speckle 3D visual added alongside the legacy visual. */}

<Steps>
  <Step title="Import the new visual">
    In the Visualizations pane, select **Import a visual from a file**. Import `Speckle Power BI 3D
    Visual.pbiviz` from `Documents/Power BI Desktop/Custom Visuals`. The new visual appears in the
    pane alongside the legacy visual.
  </Step>
  <Step title="Add the new visual and fields">
    Add the imported visual to your report. Check that its fields include **Object Keys**. The older
    visual has **Object IDs**. Drag `Objects[Model Info]` into **Model Info**, `Objects[Object Key]`
    into **Object Keys**, tooltip fields into **Object Data (Tooltip)**, and the previous category
    field into **Color By**. Recreate any color rules on the new Edit page. You should see your
    model in the new visual.
  </Step>
  <Step title="Check the report before removing the legacy visual">
    Refresh the report and test its filters, charts, and tooltips. Confirm that the new visual shows
    the expected objects before deleting the legacy visual from that page.
  </Step>
</Steps>

<Note>
  Installing a connector update copies the visual file to your Documents folder. Visuals already
  imported into reports do not update automatically through AppSource.
</Note>

### Remove the old queries

Delete the `GetByUrl` queries after no visual, measure, or relationship references them.

## Retained functions

Existing M functions remain available. Data-shaping helpers still expect the legacy `GetByUrl`
table shape. The project issues function is independent of both object data paths.

| Function                                     | Behavior                                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `Speckle.GetByUrl(url, ExpandProperties)`    | Keeps its 3.x contract and reads JSON versions only. It is no longer the published Get Data entry |
| `Speckle.GetStructuredData(url)`             | Returns the legacy flat objects table from JSON                                                   |
| `Speckle.SendToServer(url)`                  | Downloads the version's raw JSON object tree                                                      |
| `Speckle.Objects.Collections`                | Shapes legacy `GetByUrl` output                                                                   |
| `Speckle.Objects.CompositeStructure`         | Shapes legacy `GetByUrl` output                                                                   |
| `Speckle.Objects.MaterialQuantities`         | Shapes legacy `GetByUrl` output                                                                   |
| `Speckle.Objects.Properties`                 | Shapes legacy `GetByUrl` output                                                                   |
| `Speckle.Models.Federate`                    | Operates on legacy `GetByUrl` shapes                                                              |
| `Speckle.Models.MaterialQuantities`          | Operates on legacy `GetByUrl` shapes                                                              |
| `Speckle.Revit.Parameters.ToNameValueRecord` | Operates on legacy `GetByUrl` shapes                                                              |
| `Speckle.Utils.ExpandRecord`                 | Operates on legacy `GetByUrl` shapes                                                              |
| `Speckle.Project.Issues(url, getReplies)`    | Remains independent of both object data paths and works with old and new reports                  |
| `Speckle.GetVersion()`                       | Returns the connector version string, unchanged                                                   |

The installer places the data connector in the current user's Documents folder. Reports opened by
that user use the installed connector. Existing `GetByUrl` queries still work when their target
version contains JSON data.

## FAQ

<AccordionGroup>
  <Accordion title="What happens if I only rename GetByUrl to GetTables in the Advanced Editor?">
    The downstream query steps still expect the old flat table and will fail. Rebuild the query from
    **Connect to Speckle (Custom)**, load Objects, and invoke Properties and Relations.
  </Accordion>
  <Accordion title="Can I keep following new versions without migrating?">
    No. Pinning to `.../models/MODEL_ID@VERSION_ID` is a recovery option. If the report must follow
    new publishes after a 4.0 authoring connector is in use, rebuild it with `Speckle.GetTables` and
    add the new visual.
  </Accordion>
  <Accordion title="What happens if I import the new visual before I migrate the queries?">
    With 2026.10.0, importing the new file leaves legacy visuals in place. A new visual needs
    `GetTables` output before it can display a model. A legacy `GetByUrl` table cannot supply its
    required fields. Keep the legacy visual until you have loaded the new tables and checked the
    report.
  </Accordion>
</AccordionGroup>
