Dashboards load models in the 2026.9 data format. You do not need
[compatibility mode](/next/it-admin/compatibility-mode) for that.

Models published with 2026.9 connectors, ACC sync that writes the new format,
and Rhino or IFC file uploads all appear in Dashboards. This includes older
versions: Speckle Server has upgraded existing version history to the new
format, so Dashboards load against your full model history, not just data
published after the fix.

A few widgets are not ported yet. Those saved instances stay on the grid as
placeholders. They keep their configuration. They do not load 2026.9-format
data until that widget is ported. See
[Dashboard widgets not yet available](/next/analytics/dashboards-widget-availability).

For building, sharing, and configuring dashboards, use the
[current Dashboards documentation](/analytics/intelligence-dashboards).

<Note>
  Compatibility mode is optional. Request it only when ACC sync or drag-and-drop still has to write
  the old format for another tool. See [Compatibility mode](/next/it-admin/compatibility-mode).
</Note>

## New widgets, not just a compatibility port

Reading 2026.9-format models is the baseline fix. Alongside it, a few widgets are new — they did not exist in Current Dashboards:

- **Dual viewer** — two Model Viewer panes in one widget, cameras synced, for comparing two models side by side.
- **Elements table** — a unified table replacing both Element table and Pivot table, built for the new data format.
- **Ratio value** and **Ratio value by property** (Beta) — a live ratio between two numbers (or a number and a per-property breakdown), traced back through its property sources, calculated fields, and filters.
- **Numeric range** (Beta) — a slider filter widget that publishes a range for other widgets to filter by.
- **Property checker** — model validation rules surfaced as a dashboard widget, rather than only in the model checker tool.

These ship alongside the format fix, not as a separate release.

## Dashboards remain the analytics product

Dashboards stay available on every plan. Workspaces without Speckle
Intelligence keep using them. Workspaces with Intelligence can use Dashboards
and [Intelligence Reports](/next/analytics/reports) side by side.

If you have built a dashboard that solves a problem in a way we have not seen
before, share it in the [forum](https://speckle.community) or email
[feedback@speckle.systems](mailto:feedback@speckle.systems).

## Intelligence Reports

For workspaces with Speckle Intelligence, **Intelligence Reports** start from
an analysis you already ran in
[Speckle Intelligence Chat](/next/analytics/intelligence). You ask a question
about your model, the chat builds the analysis, and you save that as a Report.

Reports can also draw on external data sources — Snowflake, Databricks, and
others — so cost rates, programme data, or benchmarks sit next to model data.

## FAQ

<AccordionGroup>
  <Accordion title="Do I need compatibility mode for Dashboards to load 2026.9 models?">
    No. Dashboards already read the 2026.9 format. Request compatibility mode only when ACC sync or
    drag-and-drop must keep writing the old format for another tool. See [Compatibility
    mode](/next/it-admin/compatibility-mode).
  </Accordion>
  <Accordion title="Why is a widget on my dashboard a placeholder?">
    That widget is not ported yet. The saved configuration stays. The list of placeholders is on
    [Dashboard widgets not yet available](/next/analytics/dashboards-widget-availability). Other
    widgets on the same dashboard still load 2026.9-format data.
  </Accordion>
  <Accordion title="What happens after 1 November 2026?">
    Compatibility mode ends. That deadline is for ACC sync and drag-and-drop format, not for
    Dashboards. Dashboards already read 2026.9-format models.
  </Accordion>
  <Accordion title="Does this cover older model versions, or only new ones?">
    All of them. Speckle Server has upgraded existing version history to the new data format, so
    Dashboards load against a model's full version history, not just versions published after the
    fix.
  </Accordion>
</AccordionGroup>
