This quickstart covers the primary Data Validation checks-and-standards flow.

## Prerequisites

- Access to a Speckle project with at least one model version
- Permission to open project Data Validation
- Plan level that supports your intended save/run scope

## Create your first check

<Steps>
  <Step title="Open project Data Validation">
    In your project, open **Data Validation** and choose **check** mode.
  </Step>
  <Step title="Select a model version for preview">
    Pick model/version context so preview runs against relevant data.
  </Step>
  <Step title="Author rules">
    Add `WHERE` and `CHECK` conditions for target requirements.
  </Step>
  <Step title="Run preview">Validate rule behavior before saving.</Step>
  <Step title="Save check">
    Name the check, select tracked model(s), and choose trigger mode (manual or auto-run
    on new versions).
  </Step>
</Steps>

## Create reusable standards

Use **standard** mode when rules should be reused across checks.

You can:

- author standards from scratch
- import IDS, COBie, or Speckle rule definitions
- create checks from standards for execution

## Understand run behavior

- Auto-run checks execute when tracked models publish new versions.
- Manual checks run on demand.
- Saved runs appear in latest + history views.

## Review and export outcomes

After runs complete:

1. open check detail
2. inspect `PASS`, `WARN`, `FAIL`, `PENDING` status distribution
3. compare historical trend
4. export BCF when issue workflow handoff is required
