## Result states

Rule and check summaries use these statuses:

- `PASS`: rule or run met pass threshold
- `WARN`: partially compliant range between warning and pass thresholds
- `FAIL`: below warning/pass requirements
- `PENDING`: no completed evaluation yet (or awaiting run data)

## Latest result vs history

- **Latest result** gives your current project signal for a check.
- **History** shows trend over time as tracked model versions change.
- Use both views together to avoid overreacting to one transient run.

When reading history, always confirm:

- Which model version triggered each run
- Whether rule edits changed baseline expectations
- Whether failures cluster by specific model or time period

## Model and version context

Checks can track one or multiple models depending on workspace plan. Each run is
tied to specific model version context, so trend interpretation should include:

- model coverage in that run
- trigger mode (manual vs auto-run)
- timestamp and authoring context

## Coordination handoff

When teams need issue-driven handoff to coordination workflows, you can export
BCF from validation outcomes.

BCF export includes topic metadata based on validation outcomes so recipients can
triage failed objects with supporting context.

## Practical review flow

<Steps>
  <Step title="Open latest check result">
    Start with current check score and top failing rules.
  </Step>
  <Step title="Drill into failing rules">
    Inspect object counts and rule conditions to separate systemic issues from edge
    cases.
  </Step>
  <Step title="Compare with history">
    Confirm whether failures are regressions, recurring debt, or resolved trends.
  </Step>
  <Step title="Share and coordinate">
    If external coordination tooling is used, include BCF export in handoff.
  </Step>
</Steps>

## FAQ

<AccordionGroup>
  <Accordion title="Why does a rule show PENDING?">
    `PENDING` appears when no completed evaluation exists yet for that rule/run context.
  </Accordion>
  <Accordion title="Can warning thresholds be customized?">
    Yes. Warning and pass thresholds can be configured globally and per rule in
    authoring flow.
  </Accordion>
  <Accordion title="Should I use latest only or history only?">
    Use both. Latest helps with immediate action; history helps with governance and
    trend confidence.
  </Accordion>
</AccordionGroup>
