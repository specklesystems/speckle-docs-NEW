This page covers Data Validation concepts, core objects, setup flow, and project-level entry
points. It does not cover dashboard widget validation paths; for widget-based validation, see
[Validation Widgets in Dashboards](/analytics/dashboards/validation-widgets).

<Warning>
  A check saved before your project moved to the 2026.9 data format can return no objects, because
  its stored rule still uses the earlier object filter. Create a new check, run preview, then save.
  See [Default scope](/analytics/data-validation/checks#default-scope).
</Warning>

## Why teams adopt it

Use it when validation rules must stay stable across iterations or across people—for
repeatable QA, shared predicates and thresholds, and pass-rate comparison as versions ship.

## Core objects

**Validation checks** execute saved rules against tracked models when you run manually or when
auto-run triggers on new versions.

A **rule** can read properties on the object itself, on a [related
object](/analytics/data-validation/checks#checks-against-related-objects) such as the wall that
hosts a door, or a [calculated value](/analytics/data-validation/checks#check-a-calculated-value).

A **result** captures one completed run with scores, per-rule statuses, counts, and failing
element links.

**History** orders past results for a check so you can compare trends across versions.

## Quickstart

The [end-to-end flow](#end-to-end-flow) is the single setup path from authoring to result review.

## End-to-end flow

You need at least one published model version in the project.

<Steps>
  <Step title="Open Run check">
    In the project sidebar, open **Data Validation**, then **Run check**.
  </Step>
  <Step title="Author or import rules">
    Use `WHERE` / `CHECK`, or select **Import IDS**, **Import COBie**, or **Import Speckle**.
  </Step>
  <Step title="Run preview">
    Validate filters on real data before save. **Run Preview** or `Ctrl+Enter` / `Cmd+Enter`.
  </Step>
  <Step title="Save">
    Set a name, optional description, scoped models, and manual or auto-run on new versions.
  </Step>
  <Step title="Track results">
    Open the check result page; expand rules and models to see filter-step counts when debugging
    failures.
  </Step>
  <Step title="Share outcomes">
    Export **BCF** from result views where coordination tooling expects it.
  </Step>
</Steps>

## Navigate from project sidebar

In the project sidebar:

- **Data Validation**
- **Run check** — draft / preview without persisting yet
- **Checks** — saved checks (name and description editable; rules and scope frozen—see Checks)

## Versions you can run against

Data Validation preview and saved-check runs need a version in the data format introduced in
2026.9. If preview does not load, publish a new version after the project has moved to the new
format. See [Speckle's new data model](/workspaces/data-model-migration).

## Progressive implementation sequence

**Explore** — run preview on real revisions first so scope errors show before saving ([Run a first
check](/analytics/data-validation/checks#run-a-first-check)).

**Persist** — save against tracked models so reruns stay comparable over time ([Operate checks over
time](/analytics/data-validation/checks#operate-checks-over-time), [Practical review
flow](/analytics/data-validation/viewing-results#practical-review-flow)).

**Scale** — set checks to auto-run so every new version is validated without anyone starting it
([Validate incoming models automatically](/workflows/validate-incoming-models-automatically)).

## FAQ

<AccordionGroup>
  <Accordion title="Where did Project standards go?">
    Project standards are being retired, and the Data Validation sidebar shows **Run check** and
    **Checks** only. Author and save checks instead; IDS and COBie imports now start a check. See
    [Project standards](/analytics/data-validation/standards).
  </Accordion>
  <Accordion title="Do checks run automatically?">
    Checks can run in manual mode or auto-run on new model versions, depending on check trigger
    settings.
  </Accordion>
  <Accordion title="Where do I inspect detailed outcomes?">
    Open the check detail page to inspect latest and historical rule outcomes. See [Viewing
    Results](/analytics/data-validation/viewing-results).
  </Accordion>
  <Accordion title="Can I still use the Model Validation widget?">
    No, not any longer. The **Model Validation** widget is no longer supported. Use the **Elements
    table** or **Property checker** in a dashboard, or a Data Validation check. Saved dashboards and
    their data are kept. See [Validation Widgets in
    Dashboards](/analytics/dashboards/validation-widgets).
  </Accordion>
</AccordionGroup>
