Data Validation in `Current` docs describes the frontend-3 workflow.

<Info>
  `Current` uses **Validation Checks** and **Standards** in the project Data Validation
  area. If you are using dashboard widgets such as Property Checker or Model Validation,
  use the [Classic Data Validation docs](/classic/analytics/data-validation/overview).
</Info>

## Core objects

- **Validation Check**: execution object that runs rules against selected models
- **Standard**: reusable rule set template that can seed new checks
- **Result**: outcome for a run (score, statuses, affected objects)
- **History**: timeline of run outcomes for a check and tracked models

## End-to-end flow

<Steps>
  <Step title="Choose mode">
    Open Data Validation in a project and choose whether you are creating a **check** or
    a **standard**.
  </Step>
  <Step title="Author or import rules">
    Define rules with `WHERE` and `CHECK`, or import from **IDS**, **COBie**, or
    **Speckle** formats.
  </Step>
  <Step title="Run preview">
    Validate your rule logic before saving so you can adjust filters and thresholds.
  </Step>
  <Step title="Save">
    Save as a check (runs over tracked models) or as a standard (reused across checks).
  </Step>
  <Step title="Track results">
    Review latest result and history trends for each check, then investigate
    fails/warnings.
  </Step>
  <Step title="Share outcomes">
    If needed, export BCF for downstream issue coordination workflows.
  </Step>
</Steps>

## Terminology bridge

Use `Current` terms in daily work:

- **Validation Check** (legacy/internal: `insight`)
- **Standard** (legacy/internal: `ruleset`)

<Note>
  You may still see `insight` and `ruleset` in technical contexts (APIs, metadata,
  migration references). In product UI and user guidance, prefer **check** and
  **standard**.
</Note>

## Plan availability

<AccordionGroup>
  <Accordion title="What Model Validation (beta) features do I get on each plan?">
    **Speckle Explore (Free):** in-session trial and preview experience; no
    persistent saved checks and no saved results history.

    **Speckle Team (Business):** persistent checks with trend/history tracking
    for one tracked model per check.

    **Speckle Enterprise:** multi-model checks, reusable standards, and
    governance-oriented history at broader team scale.

  </Accordion>
</AccordionGroup>

## FAQ

<AccordionGroup>
  <Accordion title="Should I start with a check or a standard?">
    Start with a **check** when you are validating one concrete requirement against
    active models. Start with a **standard** when you want reusable rules that multiple
    checks can inherit.
  </Accordion>
  <Accordion title="Do checks run automatically?">
    Checks can run in manual mode or auto-run on new model versions, depending on check
    trigger settings.
  </Accordion>
  <Accordion title="Where do I inspect detailed outcomes?">
    Open the check detail page to inspect latest and historical rule outcomes. See
    [Viewing Results](/analytics/data-validation/viewing-results).
  </Accordion>
  <Accordion title="Can I still use dashboard widgets for validation?">
    Yes. Widget-first validation remains documented under [Classic Data
    Validation](/classic/analytics/data-validation/overview).
  </Accordion>
</AccordionGroup>
