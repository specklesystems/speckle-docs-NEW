Use this page when your validation work happens inside **Intelligence dashboards** with widgets.

This is a focused sub-guide of [Common workflows](/analytics/dashboards/common-workflows).

## Which path are you on?

- **Dashboard widget path**: a **Property checker** widget shows a pass rate for one rule on a
  dashboard, next to your other charts.
- **Data Validation path**: a saved check in the dedicated Data Validation area runs many rules on
  tracked models and keeps a history of results.

<Info>
  If you want a quick pass/fail view on a dashboard, start here. If you need saved rules that run on
  every new version, use [Data Validation](/analytics/data-validation/overview).
</Info>

## Check a rule with Property checker

<Steps>
  <Step title="Open a dashboard">Create or open a dashboard with your model as a data source.</Step>
  <Step title="Add Property checker">
    Add **Property checker** from the **Basics** group in the widget panel.
  </Step>
  <Step title="Define the conditions">
    Select **Configure conditions** and add conditions. The last condition is the check; the ones
    above it narrow which elements are checked.
  </Step>
  <Step title="Read the result">
    The widget shows the pass rate. Turn on **Color objects** to see passing and failing elements.
  </Step>
</Steps>

## How conditions work

| Step    | What it does                                                 |
| ------- | ------------------------------------------------------------ |
| `WHERE` | The first condition: which elements to consider              |
| `AND`   | Further conditions that narrow the same set                  |
| `CHECK` | The last condition: what must be true for an element to pass |

Each condition is a property, a predicate, and a value where the predicate needs one. Predicates
cover existence, comparison, pattern matching, and numeric ranges. See
[Filters](/analytics/dashboards/filters) for the full predicate list.

## Reading results

- The chart shows the pass rate for the elements that reach the `CHECK` step.
- The step list shows how many elements remain after each `WHERE`, `AND`, and `CHECK` condition, so
  you can see where elements drop out.
- **Explain this value** shows how the widget arrived at its number.
- **Color objects** colours passing and failing elements in the model.

## Move rules from a Model Validation widget

The **Model Validation** widget is retired: you can't add it to a dashboard. Use a **Property
checker** for a pass rate on a dashboard, and a Data Validation check for rulesets. To bring an
existing ruleset across, open **Model validation (beta)** in the sidebar of a dashboard that has
the widget, export the ruleset as JSON, then select **Import Speckle** in a new Data Validation
check. See [Import rules from IDS, COBie, or
Speckle](/analytics/data-validation/checks#import-rules-from-ids-cobie-or-speckle).

## When to move to a Data Validation check

Use a Data Validation check when you need:

- many rules evaluated together, with severity and messages
- results tracked over time for each model version
- checks that run automatically on every new version
- BCF export of failing elements

See [Validate incoming models automatically](/workflows/validate-incoming-models-automatically) for
the end-to-end pattern.
