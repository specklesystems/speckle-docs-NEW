## How configuration is split

- **Workspace configuration** controls security, identity, compliance, and workspace-wide behavior.
- **Project configuration** controls access and operations for one project.

## Workspace settings

Open workspace **Settings** when a change should apply to the whole workspace. Workspace members
can open most settings pages. Only workspace admins can change workspace-level controls. Some items
appear only when the plan or your role includes them.

<Note>
  Workspaces are available on Speckle Cloud and on Speckle Enterprise Server. For self-hosted setup,
  see [Enterprise license](/developers/server/deployment/enterprise-license#enable-workspaces).
</Note>

<Steps>
  <Step title="Open the workspace">
    Sign in and open the workspace. You should see **Settings** at the bottom of the left sidebar.
  </Step>
  <Step title="Open Settings">
    Select **Settings**. The sidebar expands into **General** followed by collapsible sections. The
    section that holds the current page opens.
  </Step>
</Steps>

### Settings map

Items appear in this order. A section shows only when at least one of its items is available to
you. A hidden item is gated by plan or permission, not missing from the product.

- **General**: name, short ID, description, logo, and the **AI features** switch. On the
  Enterprise and Unlimited plans, the AI card also holds two more switches: **Only workspace
  admins can enable AI** and **Disable public sharing of AI conversations**. Everyone who can open
  Settings sees this page. Only workspace admins can save changes, turn AI features off, or change
  the two switches. See [Turn AI features off for the
  workspace](/it-admin/setup#turn-ai-features-off-for-the-workspace) and [Enterprise controls for
  AI](/it-admin/setup#enterprise-controls-for-ai).
- **Members & access**
  - **Roles**: an overview of workspace roles. It appears only where it is enabled for the
    workspace. See [Roles and permissions](/workspaces/roles-and-seats).
  - **Security**: discoverability, domain protection, SSO, and SCIM. See [Workspace
    discoverability](/workspaces/workspace-discoverability), [Domain
    protection](/workspaces/domain-protection), [SSO](/workspaces/sso), and
    [SCIM](/workspaces/scim).
  - **Tokens**: workspace share tokens for read-only access to models or
    dashboards. Revoke one token, or use **Revoke all**.
  - **Support**: support sessions. It appears when Admin Support Mode is enabled. See [Admin Support
    Mode](/it-admin/support-mode).
- **Projects**
  - **Metadata**: the fields every project in the workspace can fill out. See [Project
    metadata](/workspaces/configuration/project-metadata).
  - **Project labels**: labels used to organize projects. See [Project
    labels](/workspaces/projects#project-labels).
  - **Issue labels**: labels used on project issues. See [Issues — labels](/3d-viewer/issues#labels).
- **Plan & billing**
  - **Usage**: activity, plan limits, and AI spend. Workspace admins see it when the plan includes
    usage analytics. See [Usage statistics](/workspaces/usage).
  - **Billing and plans**: plan, payment, and Customer Portal. See [Billing](/workspaces/billing).
  - **Data residency**: where workspace data is stored. See [Data
    residency](/workspaces/data-residency).
- **AI**
  - **Rules**: standing instructions Speckle Intelligence follows in every conversation. Members
    can open it; only workspace admins can change rules. See [AI
    Rules](/analytics/intelligence-rules).
  - **Skills**: reusable playbooks for Speckle Intelligence Chat. See [Intelligence skills](/analytics/intelligence-skills).
  - **Conversations**: the workspace-wide list of Chat conversations. Workspace admins only.
- **Automate**
  - **Functions**: the Automate functions available to projects in this workspace, including
    **Regenerate token...**. See [Speckle Automate](/developers/automate/introduction).

<Note>
  On self-hosted servers, Admin Support Mode is available only on Speckle Enterprise Server. See
  [Enterprise license — Admin Support
  Mode](/developers/server/deployment/enterprise-license#optional-admin-support-mode).
</Note>

<Note>
  On self-hosted servers, Speckle Automate is available only on Speckle Enterprise Server. See
  [Enterprise license —
  Automate](/developers/server/deployment/enterprise-license#optional-automate).
</Note>

Use workspace settings when policies should be consistent across all projects in the workspace.
For invites and team membership, open **Team** in the workspace sidebar. See [Invites and team
membership](/workspaces/inviting).

## Project configuration

Open a project, then **Settings** in the project sidebar, when your change should affect one project
only. Project settings has **General**, **Webhooks**, **Tokens**, and **Automations** (when Automate is
available). Workspace settings do not replace project settings.

### Manage project collaborators

Projects can be shared with workspace members and, depending on workspace rules, with guest collaborators.
Project visibility and membership together determine who can view and edit project content.
Open **Collaborators** in the project sidebar to view and manage project access.

### Access levels

A project can have one visibility state:

- **Workspace**: Accessible to workspace members.
- **Private**: Accessible only to project collaborators and admins.
- **Public**: Accessible to anyone with the link in the web interface and API.

<Steps>
  <Step title="Open project settings">Open the project, then open project settings.</Step>

<Warning>

  switching to Public visibility.
</Warning>

### Share tokens

<Frame>
  <img
    src="/images/workspaces/configuration/project-share-tokens.png"
    alt="Project share tokens list with Type, Label, Expires, Created and Last used columns"
  />
</Frame>

In **Project settings -> Tokens**, you can create share tokens that give read-only access.

Share tokens are commonly used for:

- Intelligence dashboards.
- Power BI syncing.

Share tokens can be revoked from the tokens list when access is no longer needed.

### Automations

In **Project settings -> Automations**, you can review and manage automations configured for that project.

This can include:

- Active sync automations connected to cloud integrations.
- Automations running your custom code.
- Enabled Speckle pre-made automations.

Use this page to check current automation status and manage what runs against project models.
For setup and implementation guidance, use the developer docs: [Speckle Automate](/developers/automate/introduction) and [Create Automation](/developers/automate/create-automation).

## FAQ

<AccordionGroup>
  <Accordion title="Why don't I see Usage, Skills, or Functions?">
    Those items are gated. **Usage** is for workspace admins on a plan that includes usage
    analytics. **Skills** appears when the workspace includes Speckle Intelligence Chat.
    **Functions** appears when Automate is available. The rest of Settings still opens.
  </Accordion>
  <Accordion title="Who can change workspace settings?">
    Workspace admins can change workspace-level settings. Members can view most
    settings pages but cannot apply workspace-level changes.
  </Accordion>
  <Accordion title="Who can change project settings?">
    Project Owners and Workspace Admins can change project
    visibility, collaborators, tokens, and automations in project settings.
  </Accordion>
  <Accordion title="When should I use workspace settings vs project settings?">
    Use workspace settings when policies should apply across all projects in a
    workspace. Use project settings when the change should apply to only one
    project.
  </Accordion>
  <Accordion title="Do labels change permissions?">
    No. Labels are for organization and filtering. Permissions are controlled by
    workspace role, project role, and project visibility.
  </Accordion>
  <Accordion title="Are issue labels and project labels managed in the same place?">
    No. Project labels are managed in **Settings -> Project labels**. Issue
    labels are managed in **Settings -> Issue labels**.
  </Accordion>
  <Accordion title="Can guests access private projects?">
    Yes, if they are explicitly added as collaborators. Private visibility
    blocks users who are not project collaborators.
  </Accordion>
  <Accordion title="Do share tokens bypass project permissions?">
    Share tokens provide scoped read-only access for specific sharing workflows.
    They do not change workspace or project roles. Revoke tokens when they are
    no longer needed.
  </Accordion>
  <Accordion title="Does SSO include automatic user provisioning and removal?">
    Not by itself. SSO handles authentication. Use [SCIM
    provisioning](/workspaces/scim) for automated provisioning and
    deprovisioning.
  </Accordion>
  <Accordion title="Can we choose both where data is stored and who controls jurisdiction?">
    [Data residency](/workspaces/data-residency) is available in Speckle Cloud
    on Enterprise plans. If you need strict sovereignty and infrastructure
    control in your own jurisdiction, use an Enterprise self-hosted deployment.
  </Accordion>
  <Accordion title="Can governance policy prevent duplicate organization workspaces?">
    Yes, on Enterprise plans. Governance controls can enforce exclusivity based
    on verified email domains. Confirm your operating model first if your
    organization intentionally uses separate regional workspaces.
  </Accordion>
</AccordionGroup>
