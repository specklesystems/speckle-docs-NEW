All models published to Speckle are organized into **Collection**s of **Object**s, with additional object relationships captured in **Proxy** items. The generic structure of a Speckle Model is as follows:

### Collections

Collections are containers and are used dictate the primary hierarchy of the objects in your model.
The **Root Collection** is the top-level collection and typically represents a file. The root collection can contain additional model-level properties, and structures called proxies.
Any collections inside the root collection typically represent organizational structures from the source application, eg. layers in Rhino, or levels in Revit.
Collections can be nested inside other collections to any depth.

### Objects

Objects are selectable, atomic elements (typically with a visual representation) in your model. 
There are three types of Objects inside Speckle Models:
- **Geometry**: a single piece of geometry, eg. a curve, mesh, brep, and more.
- **Data Object**: a group of geometry representing a BIM element with a name and properties, eg. a stacked wall.
- **Instance**: a transform and pointer to a Definition proxy, representing a block in CAD softwares.

### Proxies

Proxies encode additional relationships between a stored value, and objects or collections in the model. For example, a render material proxy contains a material value, and a list of application ids of any objects or collections that use the material.

### Additional Model Info

The root collection may also have additional fields that are dynamically attached, depending on the source application or file type. 
These fields apply to the entire model version that is published, and may contain other types of objects (such as cameras for views).
