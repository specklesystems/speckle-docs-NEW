## Environment Files

Copy the example files to configure your environment:

```bash
cp packages/server/.env.example packages/server/.env
cp packages/server/.env.test-example packages/server/.env.test
cp packages/frontend-2/.env.example packages/frontend-2/.env
```

## Key Variables

### Server Configuration

```env
SPECKLE_SERVER_URL=http://localhost:3000
NODE_ENV=development
PORT=3000
```

### Database

```env
POSTGRES_DB=speckle
POSTGRES_USER=speckle
POSTGRES_PASSWORD=speckle
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
```

### Storage

```env
REDIS_URL=redis://localhost:6379
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD=minioadmin
MINIO_ENDPOINT=localhost
MINIO_PORT=9000
```

### Security

```env
SESSION_SECRET=your-session-secret
```

## Email

### Workspace domain requests

When a workspace admin [requests a domain](/workspaces/domain-protection#request-a-domain-you-cannot-verify) they have no verified email on, server admins are notified in the app and by email. Set this variable to copy that email to another inbox:

```env
WORKSPACE_DOMAIN_REQUEST_SUPPORT_EMAIL=
```

Leave it unset to use the server's admin contact (Server settings, **Admin contact**). If that contact is empty too, only server admins are notified. If the inbox is the same address as a server admin, that person receives one email.

A self-hosted server has no Speckle address built in. Speckle receives these requests only if this variable, or the admin contact, is set to an address at Speckle.

On Kubernetes, set `server.email.workspaceDomainRequestInbox`. See [Configure your deployment](/developers/server/deployment/kubernetes-with-helm#configure-your-deployment).

## Production

For production, ensure you:

- Use strong secrets for SESSION_SECRET
- Set NODE_ENV=production
- Configure proper email settings
- Use secure database credentials
