This guide shows how to enhance your Speckle server configuration beyond the basic [Getting Started](/developers/server/getting-started) setup. **Start with the getting started guide first**, then use these proven, low-risk options to improve your server.

## Before You Begin

Make sure you have:

1. ✅ **Completed the [Getting Started](/developers/server/getting-started) guide**
2. ✅ **A working Speckle server** running with the basic configuration
3. ✅ **Backed up your current `docker-compose.yml`** file

## Essential Security Improvements

Create a `.env` file to replace hardcoded credentials (this is **highly recommended**):

```bash
# .env file
SESSION_SECRET=your-very-secure-random-secret-key
POSTGRES_PASSWORD=your-secure-database-password
MINIO_ROOT_PASSWORD=your-secure-minio-password
```

Update your docker-compose.yml:

```yaml
speckle-server:
  # ... existing config ...
  environment:
    # ... existing environment variables ...
    SESSION_SECRET: ${SESSION_SECRET}
    POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    S3_SECRET_KEY: ${MINIO_ROOT_PASSWORD}

minio:
  # ... existing config ...
  environment:
    MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
```

## Safe Database Performance Tuning

Add these conservative performance optimizations to your existing PostgreSQL service:

```yaml
postgres:
  # ... existing config from getting started ...
  environment:
    # ... existing environment variables ...
    POSTGRES_SHARED_BUFFERS: 128MB
    POSTGRES_MAINTENANCE_WORK_MEM: 32MB
    POSTGRES_WORK_MEM: 2MB

  healthcheck:
    test: ['CMD-SHELL', 'pg_isready -U speckle']
    interval: 30s
    timeout: 10s
    retries: 3
```

## Reliable Redis Configuration

Add basic memory management to your existing Redis service:

```yaml
redis:
  # ... existing config from getting started ...
  command: redis-server --appendonly yes --maxmemory 256mb --maxmemory-policy allkeys-lru

  healthcheck:
    test: ['CMD', 'redis-cli', 'ping']
    interval: 30s
    timeout: 10s
    retries: 3
```

## Production Domain Configuration

If you have a custom domain, add to your `.env` file:

```bash
CANONICAL_URL=https://your-domain.com
FRONTEND_ORIGIN=https://your-domain.com
```

Update your docker-compose.yml:

```yaml
speckle-server:
  # ... existing config ...
  environment:
    # ... existing environment variables ...
    CANONICAL_URL: ${CANONICAL_URL}
    FRONTEND_ORIGIN: ${FRONTEND_ORIGIN}

speckle-frontend-2:
  # ... existing config ...
  environment:
    # ... existing environment variables ...
    NUXT_PUBLIC_API_ORIGIN: ${CANONICAL_URL}
    NUXT_PUBLIC_BASE_URL: ${CANONICAL_URL}
```

## Improved Service Dependencies

Enhance service startup reliability:

```yaml
speckle-server:
  # ... existing config ...
  depends_on:
    postgres:
      condition: service_healthy
    redis:
      condition: service_healthy
    minio:
      condition: service_started
```

## Conservative Performance Tuning

Add these safe performance settings to your `.env` file:

```bash
MAX_FILE_SIZE=50MB
UPLOAD_TIMEOUT=300000
RATE_LIMIT_MAX=50
RATE_LIMIT_WINDOW=900000
```

Update your docker-compose.yml:

```yaml
speckle-server:
  # ... existing config ...
  environment:
    # ... existing environment variables ...
    MAX_FILE_SIZE: ${MAX_FILE_SIZE:-50MB}
    UPLOAD_TIMEOUT: ${UPLOAD_TIMEOUT:-300000}
    RATE_LIMIT_WINDOW: ${RATE_LIMIT_WINDOW:-900000}
    RATE_LIMIT_MAX: ${RATE_LIMIT_MAX:-50}
```

## Environment Variables Summary

Complete `.env` file with only essential variables:

```bash
# Security (highly recommended)
SESSION_SECRET=your-very-secure-random-secret-key
POSTGRES_PASSWORD=your-secure-database-password
MINIO_ROOT_PASSWORD=your-secure-minio-password

# Domain (only if you have a custom domain)
CANONICAL_URL=https://your-domain.com
FRONTEND_ORIGIN=https://your-domain.com

# Performance tuning (conservative defaults)
MAX_FILE_SIZE=50MB
UPLOAD_TIMEOUT=300000
RATE_LIMIT_MAX=50
RATE_LIMIT_WINDOW=900000
```

## Testing Your Changes

1. **Apply changes incrementally** - Start with security improvements
2. **Test each section** - Verify the server still works after each change
3. **Monitor resource usage** - Watch memory and CPU consumption
4. **Keep your backup** - You can always revert if something breaks

<Note>
  **Important**: Always start with the [Getting
  Started](/developers/server/getting-started) guide first. These configurations
  are proven safe but should still be tested in your environment.
</Note>
