When you run Speckle on your own infrastructure, some releases change what
your deployment needs from you: new chart defaults, background data
migrations, removed components. This guide is the standing entry point for
those changes. Each release with operator-visible changes gets its own page
here, published when the release ships.

## The upgrade ladder

Starting with 2026.7, upgrades between release lines must be applied **in
order**. Each rung includes work that the next rung depends on:

1. **2026.6 or earlier → 2026.7.** Upgrading to 2026.7 is a hard
   requirement before anything later. 2026.7 turns on the
   objects-to-DuckDB data migration by default, and that migration must
   fully drain before you move on. See the
   [2026.7 upgrade page](/developers/server/upgrades/2026-7).
2. **2026.7 → 2026.8.** 2026.8 introduces the bundle migration, which
   builds on the packfiles produced in 2026.7. Running it to completion is
   **mandatory**, not optional. Nothing in the software stops you from
   skipping it; this documentation is the enforcement, and skipping it
   breaks the next rung.
3. **2026.8 → 2026.9.** 2026.9 is a **one-way door**. Its database
   migrations are irreversible: there is no downgrade path from 2026.9
   back to 2026.8. Enter it only after the 2026.8 migration has completed.

<Warning>
  Do not skip a rung, and do not enter 2026.9 with an incomplete 2026.8 migration. Skipping destroys
  no data, but versions that missed a migration step will render blank in the viewer and fail
  previews on 2026.9 until the migration catches up. Recovery is forward-only: complete the skipped
  migration; never attempt a downgrade.
</Warning>
