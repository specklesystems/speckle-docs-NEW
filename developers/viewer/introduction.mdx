<Warning>
  The published `@speckle/viewer` package has no loader for bundles. If your app imports the package
  and loads Speckle data itself, a bundle version renders nothing. See [Loading Speckle
  data](#loading-speckle-data) for the two ways to keep rendering.
</Warning>

Speckle lets you view 3D models directly in your web browser. The Speckle viewer is the component that makes this possible, rendering large 3D models in your browser at rapid speeds.

Speckle has made the Speckle viewer available as an Open Source project and freely available component which you can use within your own code or website.

This section of the documentation explains what the Speckle viewer is and how to build upon it. We provide full documentation, explaining the concepts behind its design, introducing some simple and more advanced examples, and providing comprehensive documentation of its Application Programming Interface (API).

## Loading Speckle data

A version's data is a [bundle](/developers/building-integrations/bundles) of parquet files, not an
object graph fetched from the objects endpoints. The published Viewer package converts object
graphs, so it needs a bridge to render a bundle.

The rest of the package is unaffected. Render pipelines, extensions, filtering, selection, queries,
the world tree and view modes all work the same way, because the change is in where the data comes
from, not in what the viewer does with it once converted.

### Am I affected?

| How your app uses the Viewer                                          | Affected |
| --------------------------------------------------------------------- | -------- |
| Imports `@speckle/viewer`, constructs a `Viewer` and a loader         | Yes      |
| Extends render pipelines or extensions, reads render views or batches | Yes      |
| Embeds the hosted web viewer in an iframe                             | No       |
| Reads data only through the GraphQL or REST API                       | No       |

### Two ways forward

  <Card title="Ask for compatibility mode" icon="clock" href="/it-admin/compatibility-mode">
    Keeps your workspace's ACC syncs and file uploads in the object-graph format until the mode ends
    on **1 November 2026**. Versions from 2026.9 connectors are bundles regardless.

Loading bundles is the route that outlasts compatibility mode. It is sample code rather than a
package release, so you own the copy and it carries a date. The guide says what it does and does
not cover.

Neither option reaches what the bundle format makes possible. The format is built for streaming
reads, sharded geometry and querying properties without materialising objects, and both options
here keep your app on the object graph it replaced: compatibility mode by producing that graph for
some data, the bridge by rebuilding it in memory. Getting the performance the format allows needs a viewer built
for it. Plan for that, and treat both of these as ways to keep working until it arrives.

<Note>
  Compatibility mode is not self-serve, and it ends for every workspace on **1 November 2026**. See
  [Compatibility mode](/it-admin/compatibility-mode) for how to request it.
</Note>

### Not the Viewer package

Two nearby cases have their own pages.

- **A data-only JavaScript app** that reads Speckle data without rendering it, built on
  `@speckle/objectloader` or `@speckle/objectloader2`, should read the bundle directly rather than
  bridging to an object graph. Start from [Building custom apps](/developers/building-apps).
- **The 3D viewer in the web app** is not this package. See [3D viewer](/3d-viewer/introduction).
