Functions live at workspace level, on the workspace **Functions** page. Creating a function sets up a private GitHub repository from a Python or C# template, with a GitHub Action that publishes each release to Speckle Automate.

<Note>
  Speckle Automate is available only on Speckle Enterprise Server. For deployment setup, see
  [Enterprise license —
  Automate](/developers/server/deployment/enterprise-license#optional-automate).
</Note>

## Authorize GitHub the first time

The first time you create a function, **New function** opens an **Authorize GitHub** dialog instead of the create flow. Select **Authorize** and approve the Speckle Automate GitHub app. You return to the **Functions** page with the **Create function** dialog open.

<Tip>
  Speckle Automate then appears in your GitHub account's authorized applications. You can revoke
  access at any time, but Speckle needs it to create new function repositories.
</Tip>

## Create the function

{/* IMAGE_PLACEHOLDER: Create function dialog — template cards, then Function name, Description, and GitHub organization fields with Create. */}

<Steps>
  <Step title="Open the Functions page">
    Open a project in the workspace, go to **Settings → Automations**, and select **View
    functions**. The workspace **Functions** page opens.
  </Step>
  <Step title="Start a new function">
    Select **New function**. The **Create function** dialog opens with the available templates.
  </Step>
  <Step title="Choose a template">
    Select the Python or C# template, then select **Next**. Each template includes the Automate SDK
    for its language.
  </Step>
  <Step title="Name and describe the function">
    Enter a **Function name** and a **Description**. The name is also the GitHub repository name.
  </Step>
  <Step title="Create the function">
    Select **Create**. The function's page opens, with its new repository linked under **Source**.
  </Step>
</Steps>

<Tip>
  When your GitHub account belongs to organizations, the dialog also shows **GitHub organization**.
  Choose one to create the repository there; leave it empty to use your personal account.
</Tip>

## What the template sets up

The new repository is ready to build and release:

- It is generated from the template project you chose.
  <Frame>
    <img
      src="/images/developers/automate/repo-title.png"
      alt="GitHub repository header showing a function repository generated from specklesystems/speckle_automate_python_example."
    />
  </Frame>
- It contains a GitHub Action (`.github/workflows/main.yml`) that builds your function and publishes each release.
  <Frame>
    <img
      src="/images/developers/automate/build-and-deploy.png"
      alt="GitHub Actions tab showing the build and deploy Speckle functions workflow from main.yml."
    />
  </Frame>
- It holds the `SPECKLE_FUNCTION_ID` and `SPECKLE_FUNCTION_TOKEN` repository secrets the action uses to publish.
  <Frame>
    <img
      src="/images/developers/automate/repo-secrets.png"
      alt="GitHub repository secrets listing SPECKLE_FUNCTION_ID and SPECKLE_FUNCTION_TOKEN."
    />
  </Frame>

The repository is private. Whether you keep it private or make it public depends on your team's open-source or source-available approach; Speckle Automate supports both. The function's page shows the repository README only when the repository is public.

<Tip>Manage repository access carefully, based on your team's workflows and requirements.</Tip>

## Publish the first release

Clone the repository, tailor the template code to your logic (see [Making Your Function](/developers/automate/making-your-function)), then create a release on GitHub. The function appears on the workspace **Functions** page, and in the **Function** list when you [create an automation](/developers/automate/create-automation), only after its first release. See [Releasing a New Version](/developers/automate/release-function-version).

<Tip>
  Try your function against project data before you release it with a [test
  automation](/developers/automate/function-testing).
</Tip>
