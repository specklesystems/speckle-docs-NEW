`AutomationContext` provides methods to attach structured annotations to objects, allowing automated analysis and validation workflows to provide meaningful feedback.

## Object Annotations

Object annotations enable attaching different types of messages (errors, warnings, informational notes, and successes) to specific objects within an automation run. This helps in tracking issues, communicating insights, and guiding decision-making.

<Tip>
  **Why annotate objects?** Annotations allow functions to return structured results, making them
  actionable in dashboards, reports, and workflows.
</Tip>

### Example

Each attach method takes the objects themselves, not their ids. The examples assume `long_beams`, `loaded_beams`, and `optimized_items` are lists of objects your function picked from the version it received.

```python main.py
from speckle_automate import AutomationContext

def automate_function(automate_context: AutomationContext):
    version_root = automate_context.receive_version()

    # Example: Structural validation
    automate_context.attach_error_to_objects(
        "Structural Analysis",
        long_beams,
        "Beam span exceeds maximum allowable length"
    )

    automate_context.attach_warning_to_objects(
        "Load Analysis",
        loaded_beams,
        "Load approaching maximum capacity"
    )

    automate_context.attach_info_to_objects(
        "Cost Analysis",
        optimized_items,
        "Material cost optimized"
    )
```

```csharp AutomateFunction.cs icon="/images/developers/sdks/csharp.svg"

```

### Annotation Types

| Type    | Method                      | Use Case                                      |
| ------- | --------------------------- | --------------------------------------------- |
| Error   | attach_error_to_objects()   | Critical issues requiring immediate action    |
| Warning | attach_warning_to_objects() | Potential concerns needing attention          |
| Info    | attach_info_to_objects()    | General insights and analysis results         |
| Success | attach_success_to_objects() | Positive outcomes or validation confirmations |

## Metadata and Customisation

Annotations can be enriched with additional metadata to improve interpretability and visualization.

<Tip>
  **Using Metadata in Annotations**: The metadata parameter allows storing arbitrary key-value pairs
  alongside annotations, making them more descriptive and informative.
</Tip>

### Example

```python
automate_context.attach_info_to_objects(
    "Cost Analysis",
    optimized_items,
    "Material cost optimized",
    metadata={"currency": "USD", "cost_saved": 5000}
)
```

### Gradient Visualization

Certain metadata keys affect how results are displayed in the Dashboards **Automate results** widget:

- `gradient: Bool`: Enables gradient-based visualization.
- `gradientValues: List[str]`: Specifies values to apply to objects.

Example:

```python
automate_context.attach_info_to_objects(
    "Gradient Visualization",
    all_objects,
    "Values applied to objects in list order",
    metadata={"gradient": True, "gradientValues": gradient_values}
)
```

## Attach results to 2026.9 models

Your function receives a version in the 2026.9 data model the same way as any other: `receive_version()` / `ReceiveVersion()` return a `Base` tree built from the version's bundle. The attach methods key each result by the object's `id` and store its `applicationId` alongside. On a tree built from a 2026.9 version, every object's `id` is set to its `applicationId`, so the call succeeds and the result matches the object in the model.

- **Attach results to objects you received.** They carry both `id` and `applicationId`. An object your function builds itself has no `id`, and the attach call raises _You can only attach {level} results to objects with an id_.
- **Treat `id` as an opaque key.** On a 2026.9 version it equals `applicationId`; on a version published before 2026.9 it is a content hash. Do not parse, compare, or cache it as a hash.
- **Re-run automations after a model is migrated.** Results stored before migration reference the old content-hashed ids, which the migrated model no longer carries. A new run keys its results by `applicationId`. A migrated object that had no `applicationId` is keyed `spk:` followed by its old content hash.

<Warning>
  `id` equalling `applicationId` comes from how Automate receives 2026.9 versions today, not from a
  documented contract. A future Automate release can change it, so do not build tooling that depends
  on it.
</Warning>

To see the results a run recorded, see [Viewing Automation Results](/developers/automate/viewing-results).

## Publish results as a new version

When a result is new model data rather than a finding on existing objects, publish it to a different model with `create_new_version_in_project` / `CreateNewVersionInProject`. In C#, Speckle.Automate.Sdk **2026.9.0-beta.4** and later also take a `BundleBuilder` and publish it in the 2026.9 format; call `WaitForVersion` before your function returns. See [Publish a bundle](/developers/automate/api-reference#publish-a-bundle) and [Function Artefacts](/developers/automate/function-artefacts).

## Best Practices

- Use the appropriate annotation type to convey severity accurately.
- Group related annotations into categories for better organization.
- Provide clear, actionable messages to aid decision-making.
- Attach each result to the objects it concerns to maintain traceability.
- Leverage metadata for richer annotations and better UI integration.

By leveraging these methods, automation functions can provide structured feedback that enhances decision-making and workflow efficiency.
