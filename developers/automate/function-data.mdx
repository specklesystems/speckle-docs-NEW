`receive_version()` / `ReceiveVersion()` returns the version that triggered the run as a `Base` tree. Your function walks that tree, picks the objects it cares about, and reports on them. This page shows the shape of the tree and the patterns that work on it.

<Note>
  Versions published before 2026.9 come back in the shape they were published in, unless the server
  has converted them: often the same `Collection` and `DataObject` tree with content-hash `id`s, and
  in older versions typed objects such as `Objects.BuiltElements.Wall`. For that object graph, see
  [Data Schema](/developers/data-schema/overview). The patterns below work on both.
</Note>

## What your function receives

For a version published in 2026.9, the tree is a projection of the version's bundle:

- **A `Collection` root.** Its `elements` hold nested `Collection`s (layers, categories, or levels, depending on the source application) and the model's objects.
- **`DataObject`s.** Each object has a `name`, its geometry in `displayValue`, and its attributes in `properties`: a nested dictionary with the type's properties and the instance's on top. They all share one `speckle_type`, `Objects.Data.DataObject`, so filter on `properties`, not on the type.
- **`id` equals `applicationId`.** Treat `id` as an opaque key. See [Attach results to 2026.9 models](/developers/automate/function-results#attach-results-to-2026-9-models).
- **Shared resources as proxies on the root.** Materials sit in `renderMaterialProxies` and instance definitions in `instanceDefinitionProxies`; placed instances are `InstanceProxy` objects.

The tree carries objects, geometry, and properties. It does not carry the relations of the [object model](/developers/object-model/overview), such as an object's level, host, or system. Objects without display geometry can also be missing from it.

<Tip>
  For relations, or for large models, load the version as a `Model` with `operations.receive3` /
  `Receive3`, passing the run's project, model, and version IDs from `automation_run_data`. See
  [Migrate to 2026.9](/developers/sdks/python/migrate-to-2026-9) (Python) or [Migrate to
  2026.9](/developers/sdks/dotnet/migrate-to-2026-9) (.NET).
</Tip>

## Walk the tree

Most functions start by flattening the tree into one list. Walk `elements` from the root: that reaches every collection and object without descending into geometry or proxies.

```python flatten.py
from collections.abc import Iterator

from specklepy.objects.base import Base


def iter_elements(obj: Base) -> Iterator[Base]:
    yield obj
    for child in getattr(obj, "elements", None) or []:
        yield from iter_elements(child)


all_objects = list(iter_elements(automate_context.receive_version()))
print(f"Flattened model contains {len(all_objects)} items.")
```

```csharp Flatten.cs icon="/images/developers/sdks/csharp.svg"
using Speckle.Sdk.Models;
using Speckle.Sdk.Models.Collections;

public static class SpeckleUtils
{
    public static IEnumerable<Base> IterElements(Base obj)
    {
        yield return obj;
        if (obj is not Collection collection)
        {
            yield break;
        }
        foreach (var child in collection.elements)
        {
            foreach (var nested in IterElements(child))
            {
                yield return nested;
            }
        }
    }
}

var allObjects = SpeckleUtils.IterElements(await context.ReceiveVersion()).ToList();
Console.WriteLine($"Flattened model contains {allObjects.Count} items.");
```

## Filter by property

To find the objects a rule applies to, keep the `DataObject`s and test their `properties`. Property names and values come from the source application: check a version in the web app to see what yours carries.

```python filter.py
from specklepy.objects.data_objects import DataObject


def collect(root, category: str) -> list[DataObject]:
    return [
        obj
        for obj in iter_elements(root)
        if isinstance(obj, DataObject)
        and (obj.properties or {}).get("category") == category
    ]


walls = collect(root, "Walls")
```

```csharp Filter.cs icon="/images/developers/sdks/csharp.svg"
using Speckle.Objects.Data;

var walls = SpeckleUtils.IterElements(root)
    .OfType<DataObject>()
    .Where(o => o.properties.TryGetValue("category", out var c) && c as string == "Walls")
    .ToList();
```

A dotted property path such as `Constraints.Base Offset` is a nested dictionary in the tree: `properties["Constraints"]["Base Offset"]`.

```python property_path.py
def get_path(properties: dict, path: str):
    value = properties
    for part in path.split("."):
        if not isinstance(value, dict):
            return None
        value = value.get(part)
    return value


offset = get_path(wall.properties or {}, "Constraints.Base Offset")
```

## Group by collection

The collections in the tree are the model's own grouping: Rhino layers, Revit categories or levels, Blender collections. To report per group, walk the tree and carry the collection each object sits in.

```python group.py
from specklepy.objects.data_objects import DataObject
from specklepy.objects.models.collections import Collection


def iter_with_collection(obj, collection=None):
    if isinstance(obj, Collection):
        for child in obj.elements:
            yield from iter_with_collection(child, obj)
    elif isinstance(obj, DataObject):
        yield collection, obj


counts: dict[str, int] = {}
for collection, obj in iter_with_collection(root):
    name = collection.name if collection else "Unknown"
    counts[name] = counts.get(name, 0) + 1
```

<Tip>
  Rules about how objects relate, such as "every floor has a level" or "every door has a host", need
  the relations a `Model` carries. Load the version with `receive3` / `Receive3` for those.
</Tip>

## Report findings, don't edit the model

Record what your function finds as results on the objects it concerns: see [Annotating Function Results](/developers/automate/function-results). Results show in the Dashboards **Automate results** widget and leave the model untouched.

To publish derived data, build a new version in a different model: see [Function Artefacts](/developers/automate/function-artefacts). Don't change the received tree and send it back. For a 2026.9 version, that tree is a compatibility view of the bundle, not the published data.
