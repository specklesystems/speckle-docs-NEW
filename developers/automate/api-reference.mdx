# Speckle Automate API Reference

This reference covers function inputs and the automation context in the Python and C# Automate SDKs. Where the two SDKs differ, the reference says so.

<Note>
  To process versions published in 2026.9, a function needs specklepy **2026.9.0b3** with the
  `bundle` extra (`specklepy[bundle]==2026.9.0b3`), or Speckle.Automate.Sdk **2026.9.0-beta.4** or
  later. A stable 2026.9.0 release replaces the beta pin.
</Note>

<Tip>
  Start with the [Quickstart Guide](/developers/automate/quickstart) to understand the basic
  concepts before using this API reference.
</Tip>

## Function Inputs

Function inputs define what users can configure when running your automation. They automatically generate forms in the web interface.

### Supported Types

| Type          | Python      | C#         | Use Case                 |
| ------------- | ----------- | ---------- | ------------------------ |
| **Text**      | `str`       | `string`   | Names, descriptions, IDs |
| **Number**    | `float`     | `double`   | Measurements, thresholds |
| **Integer**   | `int`       | `int`      | Counts, indices          |
| **Boolean**   | `bool`      | `bool`     | Toggle options           |
| **Selection** | `Enum`      | `enum`     | Choose from options      |
| **Secret**    | `SecretStr` | `[Secret]` | API keys, passwords      |

### Validation Attributes

| Validation   | Python                         | C#                                   | Description            |
| ------------ | ------------------------------ | ------------------------------------ | ---------------------- |
| **Required** | `Field(...)`                   | `[Required]`                         | Field must be provided |
| **Length**   | `min_length=1, max_length=100` | `[MinLength(1)]`, `[MaxLength(100)]` | String length limits   |
| **Range**    | `gt=0, lt=100`                 | `[Range(0, 100)]`                    | Number value limits    |
| **Pattern**  | `pattern=r"^[A-Z]+$"`          | `[RegularExpression("^[A-Z]+$")]`    | Regex validation       |

In C#, `FunctionInputs` must be a `struct`: the runner's `Main<TInput>` constrains `TInput` to a struct, so a class does not compile. Set defaults with `[DefaultValue]`.

### Example: Simple Inputs

<CodeGroup dropdown>

```python simple_inputs.py
from speckle_automate import AutomateBase
from pydantic import Field

class FunctionInputs(AutomateBase):
    project_name: str = Field(
        title="Project Name",
        description="Enter the project identifier"
    )

        title="Maximum Length",
        description="Maximum allowed length in meters"
    )

    include_analysis: bool = Field(
        default=True,
        title="Include Analysis",
        description="Whether to perform detailed analysis"
    )
```

## Automation Context

The automation context is your function's interface to Speckle. It gives you the run's data, an authenticated client, and the methods for reporting results. In Python your function receives an `AutomationContext`. In C# it receives an `IAutomationContext`: the concrete `AutomationContext` class is internal, so type your parameters with the interface.

### Properties

<ResponseField name="automation_run_data / AutomationRunData" type="AutomationRunData">
  Metadata about the current run: project ID, server URL, automation and run IDs, and the triggers
  that started it.
</ResponseField>

<ResponseField name="speckle_client / SpeckleClient" type="SpeckleClient / IClient">
  Pre-configured, authenticated client for Speckle API calls.
</ResponseField>

Your function inputs are not a context property. They arrive as the second argument of your function.

<Info>
  `speckle_client` gives you the rest of the SDK: everything in
  [specklepy](/developers/sdks/python/introduction) (Python) or
  [Speckle.Sdk](/developers/sdks/dotnet/introduction) (C#) is available inside your function. For
  generated specklepy reference, see the [specklepy API
  documentation](https://specklepy.speckle.systems/specklepy/api/client/).
</Info>

### Methods

The Python methods are synchronous: call them without `await`, from a plain `def` function. In C#, `ReceiveVersion`, `CreateNewVersionInProject`, `WaitForVersion`, and `StoreFileResult` return a `Task`; the status and attach methods are synchronous.

| Python                                                       | C#                                                     | Returns                     |
| ------------------------------------------------------------ | ------------------------------------------------------ | --------------------------- |
| `receive_version()`                                          | `ReceiveVersion()`                                     | `Base` / `Task<Base>`       |
| `mark_run_success(status_message, version_result=None)`      | `MarkRunSuccess(statusMessage)`                        | Nothing                     |
| `mark_run_failed(status_message, version_result=None)`       | `MarkRunFailed(statusMessage)`                         | Nothing                     |
| `mark_run_exception(status_message)`                         | `MarkRunException(statusMessage)`                      | Nothing                     |
| `attach_error_to_objects(category, affected_objects, ...)`   | `AttachErrorToObjects(category, affectedObjects, ...)` | Nothing                     |
| `attach_warning_to_objects(category, affected_objects, ...)` | `AttachWarningToObjects(...)`                          | Nothing                     |
| `attach_info_to_objects(category, affected_objects, ...)`    | `AttachInfoToObjects(...)`                             | Nothing                     |
| `attach_success_to_objects(category, affected_objects, ...)` | `AttachSuccessToObjects(...)`                          | Nothing                     |
| `create_new_version_in_project(root_object, model_id, ...)`  | `CreateNewVersionInProject(rootObject, model, ...)`    | `Version` / `Task<Version>` |
| Not in Python                                                | `CreateNewVersionInProject(bundle, model, ...)`        | `Task<SendResult>`          |
| Not in Python                                                | `WaitForVersion(sent, timeout)`                        | `Task<Version>`             |
| `store_file_result(file_path)`                               | `StoreFileResult(filePath)`                            | blob ID `str` / `Task`      |
| `set_context_view(resource_ids=None, ...)`                   | `SetContextView(resourceIds, ...)`                     | Nothing                     |

### Getting model data

```python receive_version.py
version_root = automate_context.receive_version()
```

```csharp ReceiveVersion.cs icon="/images/developers/sdks/csharp.svg"
Base versionRoot = await context.ReceiveVersion();
```

Returns the version that triggered the run as a `Base` tree. For the shape of that tree, see [Handling Data in Functions](/developers/automate/function-data).

### Status reporting

Report the run's final status with one of these methods. If you call more than one, the last call wins.

```python status_reporting.py
automate_context.mark_run_success("All walls have a Mark")
automate_context.mark_run_failed("12 walls have no Mark")
automate_context.mark_run_exception("Could not read the model")
```

```csharp StatusReporting.cs icon="/images/developers/sdks/csharp.svg"
context.MarkRunSuccess("All walls have a Mark");
context.MarkRunFailed("12 walls have no Mark");
context.MarkRunException("Could not read the model");
```

<ParamField name="status_message / statusMessage" type="str / string" required>
  A message explaining the status. For failures, say what to fix.
</ParamField>

<ParamField name="version_result" type="dict | None">
  Python only, on `mark_run_success` and `mark_run_failed`: an optional JSON-serialisable dictionary
  attached to the run's results.
</ParamField>

<Tip>
  If your function returns without reporting a status, the runner marks the run successful with a
  warning message. If it throws, the runner marks the run as an exception and writes the error to
  the run log.
</Tip>

<Warning>
  In C#, the runner keeps only a failed or succeeded status when your function returns. A run marked
  with `MarkRunException` is replaced by that warning success, so throw instead.
</Warning>

### Annotating objects

Attach a result to the objects it concerns. Pass the objects themselves, not their IDs.

```python annotating_objects.py
automate_context.attach_error_to_objects(
    category="Missing property",
    affected_objects=walls_without_mark,
    message="No value for Mark",
    metadata={"property": "Mark"},
)
```

```csharp AnnotatingObjects.cs icon="/images/developers/sdks/csharp.svg"
context.AttachErrorToObjects(
    category: "Missing property",
    affectedObjects: wallsWithoutMark,
    message: "No value for Mark",
    metadata: new Dictionary<string, object> { ["property"] = "Mark" }
);
```

<ParamField name="category" type="str / string" required>
  A short tag that groups related results, for example "Missing property".
</ParamField>

<ParamField
  name="affected_objects / affectedObjects"
  type="Base | list[Base] / IReadOnlyCollection<Base>"
  required
>
  The objects the result applies to. Each must have an `id`, so pass objects you received. Python
  also accepts an empty list for a version-level result; C# throws on an empty collection.
</ParamField>

<ParamField name="message" type="str / string">
  An optional message explaining the result.
</ParamField>

<ParamField name="metadata" type="dict / Dictionary<string, object>">
  Optional key-value data stored with the result. See [Annotating Function
  Results](/developers/automate/function-results#metadata-and-customisation).
</ParamField>

<ParamField name="visual_overrides / visualOverrides" type="dict / Dictionary<string, object>">
  Optional, result-specific 3D visual overrides.
</ParamField>

`attach_result_to_objects` / `AttachResultToObjects` takes the same arguments after a leading `level` (`ObjectResultLevel`).

### Creating new model versions

Both SDKs refuse to publish to the model that triggered the run, so an automation cannot trigger itself.

```python create_new_version.py
version = automate_context.create_new_version_in_project(
    root_object,
    model_id=target_model_id,
    version_message="Annotated walls",
)
```

```csharp CreateNewVersion.cs icon="/images/developers/sdks/csharp.svg"
var version = await context.CreateNewVersionInProject(
    rootObject,
    targetModel,
    versionMessage: "Annotated walls"
);
```

<ParamField name="root_object / rootObject" type="Base" required>
  The data to publish as the new version.
</ParamField>

<ParamField name="model_id / model" type="str / Model" required>
  The target model: its ID in Python, the `Model` itself in C#. It must not be the triggering model.
</ParamField>

<ParamField name="version_message / versionMessage" type="str / string">
  The version message. Defaults to an empty string.
</ParamField>

Returns the new `Version` and records it on the run's results. Its id is reserved: the version appears once the server finishes processing it, so wait before you read it back in the same run. See [Wait for the version](/developers/migration/publish-through-ingestions#wait-for-the-version).

#### Publish a bundle

In C#, Speckle.Automate.Sdk **2026.9.0-beta.4** and later add a `CreateNewVersionInProject` overload that takes a `BundleBuilder`. It publishes through a model ingestion, like [`Send3`](/developers/sdks/dotnet/api-reference/operations), and returns a `SendResult` as soon as the upload completes. The server creates the version when it finishes ingesting, so call `WaitForVersion` before your function returns. Otherwise the run's result links can point at a version that does not exist yet.

```csharp PublishBundle.cs icon="/images/developers/sdks/csharp.svg"
var sent = await context.CreateNewVersionInProject(bundle, targetModel, "Analysis results");
var version = await context.WaitForVersion(sent);
```

<ParamField name="bundle" type="BundleBuilder" required>
  The bundle to publish. The call finishes the builder, so you cannot reuse it.
</ParamField>

<ParamField name="timeout" type="TimeSpan?">
  `WaitForVersion` only. How long to wait for the ingestion. With no value, it waits until the
  ingestion ends. It throws a `SpeckleException` if the ingestion fails, and a `TimeoutException` if
  the timeout passes first.
</ParamField>

## Working with Speckle Data

`receive_version()` / `ReceiveVersion()` return a `Base` tree. For a version published in 2026.9, that tree is a `Collection` root whose `elements` hold nested `Collection`s and `DataObject`s, each with `name`, `displayValue`, and `properties`. [Handling Data in Functions](/developers/automate/function-data) shows how to walk and filter it.

## Complete Function Example

This function checks that every object in a chosen category has a value for a chosen property. It fails the run and flags the objects that do not.

<CodeGroup dropdown>

```python main.py
from pydantic import Field
from speckle_automate import (
    AutomateBase,
    AutomationContext,
    execute_automate_function,
)
from specklepy.objects.base import Base
from specklepy.objects.data_objects import DataObject


class FunctionInputs(AutomateBase):
    category: str = Field(
        default="Walls",
        title="Category",
        description="Check objects whose category property matches this value",
    )
    required_property: str = Field(
        default="Mark",
        title="Required property",
        description="Flag objects in the category with no value for this property",
    )


def iter_elements(obj: Base):
    yield obj
    for child in getattr(obj, "elements", None) or []:
        yield from iter_elements(child)


def automate_function(
    automate_context: AutomationContext, function_inputs: FunctionInputs
) -> None:
    root = automate_context.receive_version()
    prop = function_inputs.required_property

    in_category = [
        obj
        for obj in iter_elements(root)
        if isinstance(obj, DataObject)
        and (obj.properties or {}).get("category") == function_inputs.category
    ]
    if not in_category:
        automate_context.mark_run_failed(f"No {function_inputs.category} objects found")
        return

    missing = [obj for obj in in_category if not (obj.properties or {}).get(prop)]
    if missing:
        automate_context.attach_error_to_objects(
            category="Missing property",
            affected_objects=missing,
            message=f"No value for {prop}",
        )
        automate_context.mark_run_failed(
            f"{len(missing)} of {len(in_category)} objects have no {prop}"
        )
    else:
        automate_context.attach_success_to_objects(
            category="Property check",
            affected_objects=in_category,
            message=f"Every object has {prop}",
        )
        automate_context.mark_run_success(f"All {len(in_category)} objects have {prop}")


if __name__ == "__main__":
    execute_automate_function(automate_function, FunctionInputs)
```

```csharp AutomateFunction.cs icon="/images/developers/sdks/csharp.svg"
using System.ComponentModel;
using System.ComponentModel.DataAnnotations;
using Speckle.Automate.Sdk;
using Speckle.Objects.Data;
using Speckle.Sdk.Models;
using Speckle.Sdk.Models.Collections;

public readonly struct FunctionInputs
{
    [Required]
    [DisplayName("Category")]
    [Description("Check objects whose category property matches this value")]
    public string Category { get; init; }

    [Required]
    [DisplayName("Required property")]
    [Description("Flag objects in the category with no value for this property")]
    public string RequiredProperty { get; init; }
}

public class AutomateFunction
{
    public async Task Run(IAutomationContext context, FunctionInputs inputs)
    {
        Base root = await context.ReceiveVersion();
        var category = inputs.Category;
        var prop = inputs.RequiredProperty;

        var inCategory = IterElements(root)
            .OfType<DataObject>()
            .Where(o => o.properties.TryGetValue("category", out var c) && c as string == category)
            .ToList();
        if (inCategory.Count == 0)
        {
            context.MarkRunFailed($"No {category} objects found");
            return;
        }

        var missing = inCategory
            .Where(o => !o.properties.TryGetValue(prop, out var v) || v is null)
            .ToList();
        if (missing.Count > 0)
        {
            context.AttachErrorToObjects("Missing property", missing, $"No value for {prop}");
            context.MarkRunFailed($"{missing.Count} of {inCategory.Count} objects have no {prop}");
        }
        else
        {
            context.AttachSuccessToObjects("Property check", inCategory, $"Every object has {prop}");
            context.MarkRunSuccess($"All {inCategory.Count} objects have {prop}");
        }
    }

    private static IEnumerable<Base> IterElements(Base obj)
    {
        yield return obj;
        if (obj is not Collection collection)
        {
            yield break;
        }
        foreach (var child in collection.elements)
        {
            foreach (var nested in IterElements(child))
            {
                yield return nested;
            }
        }
    }
}
```

</CodeGroup>
