## Function Code Anatomy

With your function project made and the code available on GitHub, you can start making it your own. Where you choose to develop (locally or codespace) is up to you. Assuming you work locally, clone the repository linked under **Source** on the function's page; the sections below cover the code architecture.

<Tip>
**.github**

This directory is for automations used to keep your function code up to date and ease the publishing process.

- `dependabot.yml`.: This specification keeps track of GitHub actions used and will recommend updates when necessary.
- `workflows/main.yml`: When you make a Release of your function code, this action will trigger and publish a revision to Speckle Automate

Leave that automation in place unless you have a custom release pipeline.

</Tip>

## Function Inputs

### Python

This is a `FunctionInputs` class subclassing `AutomateBase` from the Python Automate SDK (`speckle_automate`, part of specklepy).

Define its properties with [Pydantic](https://docs.pydantic.dev/latest/usage/models/) `Field` objects to control the fields shown in the function inputs UI. A `SecretStr` field is a secret: Automate masks it in the UI and stores it encrypted.

```python main.py
from enum import Enum

from pydantic import Field
from speckle_automate import AutomateBase


class Selection(str, Enum):
    DEFAULT = "default"
    OPTION_2 = "option 2"
    OPTION_3 = "option 3"


class FunctionInputs(AutomateBase):
    text_input: str = Field(
        title="Text Input",
        description="Values given in this field will be available with the `text_input` key.",
    )

    scalar_value: float = Field(
        default=25.0,
        title="Numerical value",
        description=(
            "Annotating a field and providing a default value will tell the "
            "Automate UI to treat the input field as a number"
        ),
    )

    selection: Selection = Field(
        default=Selection.DEFAULT,
        title="Select an option",
        description="An Enum type gives the UI a drop-down, preselecting the default value",
    )
```

### C# (.NET)

`FunctionInputs` must be a `struct`.

```csharp FunctionInputs.cs icon="/images/developers/sdks/csharp.svg"
using System.ComponentModel;
using System.ComponentModel.DataAnnotations;

public readonly struct FunctionInputs
{
    [Required]
    public string TextInput { get; init; }

    [Range(0.0, 100.0)]
    public double ScalarValue { get; init; }

    [DisplayName("Specific Input Title")]
    [Description("This is a description for the example input.")]
    public string DecoratedInput { get; init; }
}
```

### Secrets Management

It is possible to flag function inputs so that the Automate UI will obfuscate them on entry in the typical web fashion (`********`). This will also cause Automate to store these as encrypted and only pass them as plain text within `AutomationContext` at runtime.

#### C# (.NET)

```csharp FunctionInputs.cs icon="/images/developers/sdks/csharp.svg"
using Speckle.Automate.Sdk.DataAnnotations;

public readonly struct FunctionInputs
{
    [Secret]
    public string SecretInput { get; init; }
}
```

#### Python

```python main.py
from pydantic import Field, SecretStr
from speckle_automate import AutomateBase


class FunctionInputs(AutomateBase):
    secret_input: SecretStr = Field(
        title="Secret Input",
        description="A password or third-party token, masked in the UI and stored encrypted",
    )
```

## Run Entry Points

In the GitHub action, there is a space to define the eventually built function as it would be executed from a command line with either `dotnet SpeckleAutomateDotnetExample.dll` or `python main.py run`, which is the general rule for all Automate functions, whether defined with the template projects or not.

### Python

The essential execution of a Python SDK function is:

```python main.py
if __name__ == "__main__":
    execute_automate_function(automate_function, FunctionInputs)
```

`FunctionInputs` is the class described earlier, and `automate_function` is the single entry point to your business logic. Define it with plain `def`, not `async def`: the runner calls it synchronously, so a coroutine would never run. You can define as many classes, external modules, and functions within your repository code, but this will be your key function.

### C# (.NET)

The template's `Program.cs` registers the Automate SDK, resolves the runner, and passes it your function:

```csharp Program.cs icon="/images/developers/sdks/csharp.svg"
using Microsoft.Extensions.DependencyInjection;
using Speckle.Automate.Sdk;

var serviceCollection = new ServiceCollection();
serviceCollection.AddAutomateSdk();
serviceCollection.AddSingleton<AutomateFunction>();
await using var container = serviceCollection.BuildServiceProvider();

var runner = container.GetRequiredService<IAutomationRunner>();
var function = container.GetRequiredService<AutomateFunction>();

return await runner.Main<FunctionInputs>(args, function.Run);
```

`FunctionInputs` is the struct described earlier. `AutomateFunction` is a class with a `Run(IAutomationContext context, FunctionInputs inputs)` method that returns a `Task`. It can hold all of your business logic, or be the entry point to the rest of your classes and methods.

<Tip>
You may rename and restructure your function code as you wish as long as these execution entry points are followed. However, it may make sense to adopt the template's structure to debug easily and allow others to follow the flow.

The main `.csproj` for dotnet functions should be renamed to reflect your function name; make sure to adjust the `workflow/main.yml` file to reflect this.

</Tip>

## Testing

Functions must be registered to Automations to trigger by events. It is recommended that you implement a structure of your project such that a lot of the business logic can be tested independently of the specifics of both the Automate environment and the Speckle data triggering the events.

To run your function locally against live project data, see [Testing Your Functions](/developers/automate/function-testing).
