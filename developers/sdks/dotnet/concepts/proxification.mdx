When you receive BIM or CAD data from a Speckle connector, objects are often grouped by level, material, layer, or instance **without duplicating geometry**. Connectors store that organization in **proxies** at the root of the package. This page covers the C# proxy types and when you need to resolve them.

For the underlying schema — proxy structure, `objects` field semantics, Definition/Instance relationships — see [Proxy Schemas](/developers/data-schema/proxy-schema). For resolution recipes, see [Working with Proxies](/developers/sdks/dotnet/guides/working-with-proxies).
</Info>

## What Are Proxies?

Proxies let an object participate in multiple organizational systems (material, level, group, instance definition) without duplicating data. They're stored at the root level of a data package and reference objects by `applicationId`.

<Info>
This page covers the C# types that represent proxies. For the underlying schema — proxy structure, `objects` field semantics, Definition/Instance relationships — see [Proxy Schemas](/developers/data-schema/proxy-schema).
</Info>

## Proxy Types in Speckle.Sdk

Proxy classes implement `IProxyCollection`, which requires an `objects` list of the source application IDs the proxy applies to:

```csharp
using Speckle.Sdk.Models.Proxies;

public interface IProxyCollection : ISpeckleObject
{
    public List<string> objects { get; set; }
}
```

Built-in proxy types include:

```csharp
using Speckle.Sdk.Models.Proxies;

var groupProxy = new GroupProxy
{
    name = "Exterior Walls",
    objects = ["wall-app-id-1", "wall-app-id-2"]
};

var colorProxy = new ColorProxy
{
    name = "Concrete",
    value = unchecked((int)0xFF808080), // ARGB
    objects = ["wall-app-id-1", "column-app-id-1"]
};
```

<Note>
Additional proxy types (materials, levels, instance definitions) follow the same `IProxyCollection` pattern with an `objects` field. Their exact shapes are documented in [Proxy Schemas](/developers/data-schema/proxy-schema).
</Note>

## Resolving Proxies After Receive

Proxies are typically found at the root of a received data package, not nested inside the objects they describe. After `Receive`, look for proxy collections and cross-reference their `objects` lists against the `applicationId` of objects found during traversal:

```csharp
var allObjects = receivedData.Flatten()
    .Where(b => b.applicationId is not null)
    .ToDictionary(b => b.applicationId!);

if (receivedData["groupProxies"] is IEnumerable<object> proxies)
{
    foreach (var proxy in proxies.OfType<GroupProxy>())
    {
        var groupedObjects = proxy.objects
            .Where(allObjects.ContainsKey)
            .Select(id => allObjects[id]);
        // groupedObjects now share proxy.name's grouping
    }
}
```

<Warning>
Exact root-level property names for proxy collections (`groupProxies`, `colorProxies`, and so on) depend on which sender populated them — check [Proxy Schemas](/developers/data-schema/proxy-schema) and, for connector-produced data, the relevant [connector schema page](/developers/data-schema/connector-index).
</Warning>

## When Proxification Matters

### As a Data Consumer (Reading from Connectors)

You will encounter proxies when you:

- Read BIM/CAD data from Revit, Rhino, ArchiCAD, AutoCAD, or other connectors
- Query by level, group, layer, or material
- Resolve instance definitions to placed geometry
- Analyze which organizational systems an object belongs to

Resolution is required when you need to find objects by proxy metadata rather than by walking raw `elements` alone.

### As a Data Producer (Publishing from .NET)

You typically do **not** create proxies when you:

- Publish simple custom data from a script or service
- Send small object graphs with `Send2` or `Send`

Speckle.Sdk handles detachment and chunking automatically when graphs grow large. Focus on understanding proxy **resolution** as a consumer unless you are building a connector that mirrors host-app organization.

## FAQ

<AccordionGroup>
  <Accordion title="Do I need to create proxies when sending from a script?">
    Usually no. Proxies are a connector pattern for host-app organization. Send your `Base` graph; let connectors produce proxy collections when converting from Revit, Rhino, and similar hosts.
  </Accordion>
  <Accordion title="Where do I find proxies after Receive?">
    At the **root** of the received package — look for collections such as `groupProxies`, `colorProxies`, or connector-specific proxy properties documented in [Proxy Schemas](/developers/data-schema/proxy-schema).
  </Accordion>
  <Accordion title="Why resolve by applicationId instead of object id?">
    Proxies reference objects by the sender's stable `applicationId`, not Speckle's content hash. Build an `applicationId` index once, then look up each id in the proxy's `objects` list.
  </Accordion>
</AccordionGroup>
