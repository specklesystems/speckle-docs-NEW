## Goal

Pick the right SpeckleSharp API for loading model data from Speckle Server and publishing results back.

## What you will learn

When to use `Receive3`/`Send3` (recommended), `Receive2` and transports (reading versions published before 2026.9), or `SendPipeline` (connectors only).

## When to use this

Before reading [Operations](/developers/sdks/dotnet/api-reference/operations) method signatures — or when you are unsure which load or publish path fits your workflow.

## Recommended approach

**For AEC automation scripts, notebooks, and Grasshopper C#:** load with **`Receive3`** and publish with **`Send3`** after the [one-time bootstrap](/developers/sdks/dotnet/getting-started/scripts-and-notebooks). No transport factory required.

**Avoid `SendPipeline` unless** you are building a desktop connector that uploads an entire host-application model.

## The paths at a glance

| Your goal                                    | API                                 | When                                                               |
| -------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------ |
| **Load or publish model data (recommended)** | **`Receive3` / `Send3`**            | **Scripts, notebooks, Grasshopper C#, most AEC automation**        |
| Load a version `Receive3` cannot load        | `Receive2`                          | Versions published before 2026.9 that the server has not converted |
| Inspect JSON locally                         | `Serialize` / `DeserializeAsync`    | No server; debugging object shape                                  |
| Move object graphs through a transport       | `Send` / `Receive` + `ITransport`   | Local-only tests; versions published before 2026.9                 |
| Experimental serializer                      | `SerializeNew`                      | Avoid in production                                                |
| Publish whole host-app model                 | `SendPipeline` + `client.Ingestion` | Desktop connectors only                                            |

<Note>
  `Send2`, `Receive2`, `Send`, and `Receive` are marked `[Obsolete]`, and Speckle does not guarantee
  them for new work. Use them only to read versions published before 2026.9. To move existing code,
  see [Migrate to 2026.9](/developers/sdks/dotnet/migrate-to-2026-9).
</Note>

## Recommended: Receive3 / Send3

`Receive3` returns a `Model`: objects with path-keyed properties and relation accessors. `Send3` publishes the objects you describe in a `BundleBuilder`; the server creates the version when it finishes processing.

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
using var model = await operations.Receive3(account, projectId, modelId, versionId, options: null, cancellationToken: default);

var sent = await operations.Send3(account, projectId, modelId, builder, options: null, cancellationToken: default);
var version = await operations.WaitForVersion(account, sent);
```

See [Publish and load a model from C#](/developers/sdks/dotnet/getting-started/quickstart) for a `BundleBuilder` walkthrough, and [Object model](/developers/object-model/overview) for how the data is shaped.

## Path A: Serialize only

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
string json = operations.Serialize(myData);
Base restored = await operations.DeserializeAsync(json);
```

Use when you need raw JSON of a `Base` object — for example, previewing a Grasshopper graph locally. For server work, use `Receive3` / `Send3`.

## Path B: Send / Receive with a transport

The transport path moves object graphs, and only works with versions published before 2026.9. `Receive` throws if you pass a 2026.9 bundle reference.

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
using var transport = provider.GetRequiredService<IServerTransportFactory>().Create(client.Account, project.id);

var (objectId, _) = await operations.Send(myData, transport, useDefaultCache: true);
var received = await operations.Receive(objectId, remoteTransport: transport);
```

Swap `ServerTransport` for `MemoryTransport` or `SQLiteTransport` for local-only workflows.

## Path C: Receive2 / Send2 (before 2026.9)

Direct URL, project id, and token, returning or taking a `Base` object graph:

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
var root = await operations.Receive2(client.ServerUrl, project.id, objectId, account.token, onProgressAction: null, cancellationToken: default);

var results = await operations.Send2(client.ServerUrl, project.id, account.token, myData, onProgressAction: null, cancellationToken: default);
```

Keep `Receive2` for reading versions published before 2026.9. On a 2026.9 version it returns a best-effort `Base` projection rather than the full data. Publish new work with `Send3` instead of `Send2`: after `Send2`, `Version.Create` only reserves an id until the server finishes processing. See [Publish through model ingestions](/developers/migration/publish-through-ingestions).

<Note>The `streamId` parameter name in these signatures refers to the project id.</Note>

## Path D: SerializeNew

Experimental — avoid for production workflows.

## Path E: SendPipeline (connectors only)

**Avoid this unless you are building a connector.** For uploading large host-application models, connectors use `SendPipeline` and `client.Ingestion`:

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
var ingestion = await client.Ingestion.Create(new ModelIngestionCreateInput(model.id, project.id, "Starting ingestion", sourceData));
var pipeline = provider.GetRequiredService<ISendPipelineFactory>()
    .CreateInstance(ingestion, client.Account, new Progress<StreamProgressArgs>(), cancellationToken: default);
await pipeline.Process(myData);
await pipeline.WaitForUpload();
```

See [Publish large models (connectors)](/developers/sdks/dotnet/guides/building-connector-scale-sends). Do not call `Version.Create` on this pathway.

## Decision guide

<AccordionGroup>
  <Accordion title="I'm loading or analysing an existing published model">
    Use **`Receive3`** — see [Build your first model analysis
    tool](/developers/sdks/dotnet/guides/build-your-first-model-analysis-tool). If the version was
    published before 2026.9 and `Receive3` cannot load it, use `Receive2`.
  </Accordion>
  <Accordion title="I'm writing a script or Grasshopper C# component">
    Use **`Receive3`** and **`Send3`** — see [Automate with
    scripts](/developers/sdks/dotnet/getting-started/scripts-and-notebooks).
  </Accordion>
  <Accordion title="I maintain code that uses Receive2, Send2, or transports">
    Move it to `Receive3` and `Send3`. Keep `Receive2` or a transport `Receive` only to read
    versions published before 2026.9 that have no bundle; Speckle does not guarantee the old calls
    for new work. See [Migrate to 2026.9](/developers/sdks/dotnet/migrate-to-2026-9) for the changes
    side by side.
  </Accordion>
  <Accordion title="I'm building a desktop connector">
    Use **Path E** — [Publish large models
    (connectors)](/developers/sdks/dotnet/guides/building-connector-scale-sends).
  </Accordion>
</AccordionGroup>
