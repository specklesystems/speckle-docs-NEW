Use **Speckle.Sdk** when you need to send or receive building-model data from a .NET app — a Grasshopper script, an automation service, or a desktop connector. It talks to Speckle Server over GraphQL and works with Speckle's object model (structured data instead of files).

**When to use it:** any .NET workflow that publishes or reads model data on Speckle Server. **Read next:** [Scripts and Notebooks](/developers/sdks/dotnet/getting-started/scripts-and-notebooks) for the shortest script path, or [Core Concepts](/developers/sdks/dotnet/concepts/overview) if you want the platform map before writing code.

## What is Speckle.Sdk?

Speckle.Sdk is a .NET library for developers who need to:

- **Send and receive** geometry and BIM data as objects, not files
- **Call Speckle Server** through a typed GraphQL client (`client.Project`, `client.Model`, `client.Version`, and more)
- **Model data with `DataObject` and `Collection`** — the ecosystem-standard containers most connectors and the viewer expect — or define a fully custom type inheriting from `Base` when you need something bespoke
- **Choose a send path** — `Send2` for scripts, transports for local cache, or `SendPipeline` for connectors
- **Work with geometry** via the companion `Speckle.Objects` package (Point, Line, Mesh, Brep, and more)

<Info>
Speckle.Sdk targets **netstandard2.0**, **net8.0**, and **net10.0**, so it runs in both modern .NET applications and older host apps (such as Revit on .NET Framework).
</Info>

## Key Features

### Object-Based, Not File-Based

Forget about files. Speckle uses **objects** as the fundamental unit of data exchange.

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
var myData = new Base
{
    ["name"] = "My first object",
    ["count"] = 42
};
```

<Note>
Instead of files, Speckle stores sets of objects in Models. Models are contained within Projects. Projects are contained within Workspaces. Learn more about organising your data in Speckle in the [User Guide](https://docs.speckle.dev/workspaces/projects).
</Note>

### Version Control for AEC Data

Every publish creates a new **version** (a snapshot in a model's history). Sending registers objects on the server; a version makes them discoverable in the UI. See [Core Concepts: orphaned objects](/developers/sdks/dotnet/concepts/overview#orphaned-objects) and the [Quickstart](/developers/sdks/dotnet/getting-started/quickstart) for the full send → version workflow.

### One-Time Setup (Not "Dependency Injection" as a Skill)

Speckle.Sdk uses dependency injection internally so connectors can share a container with host apps. **Scripts and notebooks:** paste the bootstrap from [Scripts and Notebooks](/developers/sdks/dotnet/getting-started/scripts-and-notebooks) once — you do not need to study DI. **Connectors and services:** see [Dependency Injection](/developers/sdks/dotnet/concepts/dependency-injection).

## Quick Example


Here's a complete example of sending geometry to Speckle:

```csharp Complete example lines icon="/images/developers/sdks/csharp.svg" expandable
using Microsoft.Extensions.DependencyInjection;
using Speckle.Sdk;
using Speckle.Sdk.Api;
using Speckle.Sdk.Api.GraphQL.Enums;
using Speckle.Sdk.Api.GraphQL.Inputs;
using Speckle.Sdk.Credentials;
using Speckle.Sdk.Models;
using Speckle.Sdk.Transports;

// Bootstrap the SDK
var services = new ServiceCollection();
services.AddSpeckleSdk(new Application("My App", "my-app"), "1.0.0");
var provider = services.BuildServiceProvider();

// Authenticate with a personal access token
var account = await provider.GetRequiredService<IAccountFactory>()
    .CreateAccount(new Uri("https://app.speckle.systems"), "your_token_here");
using var client = provider.GetRequiredService<IClientFactory>().Create(account);

// Create a project
var project = await client.Project.Create(new ProjectCreateInput("My First Speckle Project", null, ProjectVisibility.Private));

// Build a Speckle object
var myData = new Base { ["greeting"] = "Hello Speckle" };

// Send it to the project
using var transport = provider.GetRequiredService<IServerTransportFactory>().Create(client.Account, project.id);
var (objectId, _) = await provider.GetRequiredService<IOperations>().Send(myData, transport, true);

// Create a model and a version pointing at the sent object
var model = await client.Model.Create(new CreateModelInput("My first model", null, project.id));
var version = await client.Version.Create(new CreateVersionInput(objectId, model.id, project.id, "My first version"));

Console.WriteLine($"Created version: {version.id}");
```

## FAQ

<AccordionGroup>
  <Accordion title="Where should I start — Scripts and Notebooks or Quickstart?">
    **Scripts and Notebooks** if you want the shortest path in a script, notebook, or Grasshopper C# component (`Send2`/`Receive2`). **Quickstart** if you want a step-by-step tour of the full workflow including `ServerTransport`.
  </Accordion>
  <Accordion title="Do I need to learn dependency injection?">
    No for scripts and notebooks — paste the bootstrap once and resolve `IOperations` and `IClientFactory`. Yes only if you build a connector or share a DI container with a host app — see [Dependency Injection](/developers/sdks/dotnet/concepts/dependency-injection).
  </Accordion>
  <Accordion title="Is the public API stable?">
    Speckle.Sdk is reliable for production use, but the public API may change between releases. Pin an explicit NuGet version and review release notes before upgrading.
  </Accordion>
</AccordionGroup>
