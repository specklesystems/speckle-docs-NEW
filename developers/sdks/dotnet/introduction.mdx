This SDK is for people who want to automate AEC workflows with C# using Speckle. You do not need to be a professional software engineer to build useful tools with it.

Likely readers include:

- Architects using Grasshopper C# nodes
- BIM managers automating QA checks
- Engineers extracting model data
- Computational designers building custom workflows
- AEC developers building plugins or integrations
- AI-assisted coders using Cursor, Claude, ChatGPT, or similar tools

**Speckle.Sdk** (SpeckleSharp) lets your C# code talk to Speckle Server — load published model versions, query objects by their properties and relations, export CSV reports, and optionally publish results back. It works from console apps, Grasshopper scripts, notebooks, and desktop plugins.

<Info>
  New to Speckle SDKs? Start with the shared [SDK introduction](/developers/sdks/introduction) for
  platform concepts and how Python and .NET relate.
</Info>

<Note>
  Moving a script written for `Receive2` and `Flatten()`? Follow [Migrate to
  2026.9](/developers/sdks/dotnet/migrate-to-2026-9) for side-by-side changes.
</Note>

[GitHub Repository](https://github.com/specklesystems/speckle-sharp-sdk)

<Warning>
  Speckle.Sdk is reliable for production use, but the public API may not be wholly stable between
  releases. Pin a specific NuGet version and review release notes before upgrading.
</Warning>

## How most workflows run

Your code uses SpeckleSharp to talk to Speckle Server. Speckle Server stores projects, models, and versions; each version holds the model's objects, their properties, and the relations between them.

In practice, most useful workflows follow this pattern:

1. Authenticate
2. Choose a project and model
3. Load a version
4. Query objects and their properties
5. Analyse or transform data
6. Optionally publish results back

<Note>
  The full mental model and diagram live in [Core
  concepts](/developers/sdks/dotnet/concepts/overview). The data model behind a version is on
  [Object model](/developers/object-model/overview).
</Note>

<Tip>
  The recommended approach for most AEC automation scripts: PAT via environment variable →
  `Receive3` on the latest version → query `model.Objects` → analyse → optional `Send3`.
</Tip>

## What you can do with SpeckleSharp

| Goal                                | What you use                                  | Learn more                                                                                                    |
| ----------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Load model data from Speckle Server | `Receive3`, `client.Version`                  | [Build your first model analysis tool](/developers/sdks/dotnet/guides/build-your-first-model-analysis-tool)   |
| Find objects by property            | `model.ObjectsWith`, `GetString`, `GetDouble` | [Migrate to 2026.9](/developers/sdks/dotnet/migrate-to-2026-9#count-and-filter-objects)                       |
| Group by level, host, or material   | `ModelObject.Level`, `Host`, `Material`       | [Relations](/developers/object-model/relations)                                                               |
| Publish results back                | `Send3`, `BundleBuilder`                      | [Publish from a script](/developers/sdks/dotnet/migrate-to-2026-9#publish-from-a-script)                      |
| Publish large host-app models       | `SendPipeline`, `client.Ingestion`            | [Publish large models (connectors)](/developers/sdks/dotnet/guides/building-connector-scale-sends) — advanced |

Under the hood, SpeckleSharp exposes typed APIs (`IClient`, `IOperations`, `Model`, `ModelObject`) — you meet them in the guides after you know the outcome you want.

<Note>
  **API reference** pages are for method lookup after you have a working script. Start with [Build
  your first model analysis
  tool](/developers/sdks/dotnet/guides/build-your-first-model-analysis-tool), not the API index.
</Note>

<Info>
  Speckle.Sdk targets **netstandard2.0**, **net8.0**, and **net10.0**, so it runs in modern .NET
  apps and older host apps such as Revit on .NET Framework.
</Info>

## One-time setup

Speckle.Sdk uses dependency injection internally so connectors can share a container with host apps. **For scripts and notebooks:** paste the bootstrap from [Automate with scripts](/developers/sdks/dotnet/getting-started/scripts-and-notebooks) once — you do not need to study DI. **Connectors and services:** see [Dependency injection (connectors)](/developers/sdks/dotnet/concepts/dependency-injection).

## Installation

```bash
dotnet add package Speckle.Sdk --version 2026.9.0-beta.7
```

<Note>
  2026.9.0-beta.7 is a prerelease; a plain `dotnet add package Speckle.Sdk` installs 2026.8, which
  has no `Receive3`. A later stable 2026.9.0 replaces the pin without changing the calls. For target
  framework details, see [Installation](/developers/sdks/dotnet/getting-started/installation).
</Note>

## FAQ

<AccordionGroup>
  <Accordion title="Where should I start?">
    [Build your first model analysis
    tool](/developers/sdks/dotnet/guides/build-your-first-model-analysis-tool) if you want a
    complete working script. [Automate with
    scripts](/developers/sdks/dotnet/getting-started/scripts-and-notebooks) if you only need the
    bootstrap snippet. [Publish and load a model from
    C#](/developers/sdks/dotnet/getting-started/quickstart) if you want to publish your own data
    from scratch.
  </Accordion>
  <Accordion title="My script uses Receive2. Can I keep it?">
    No, not for new work. Update to Speckle.Sdk **2026.9.0-beta.7** and load with `Receive3`: older
    builds get a 404 on versions from a 2026.9 connector, and Speckle does not guarantee they keep
    working against current servers. Keep `Receive2` only to read versions published before 2026.9.
    See [Migrate to 2026.9](/developers/sdks/dotnet/migrate-to-2026-9).
  </Accordion>
  <Accordion title="Do I need to learn dependency injection?">
    No for scripts and notebooks — paste the bootstrap once and resolve `IOperations` and
    `IClientFactory`. Read [Dependency injection
    (connectors)](/developers/sdks/dotnet/concepts/dependency-injection) only if you build a
    connector or share a DI container with a host app.
  </Accordion>
  <Accordion title="Is the public API stable?">
    Speckle.Sdk is reliable for production use, but the public API may change between releases. Pin
    an explicit NuGet version and review release notes before upgrading.
  </Accordion>
</AccordionGroup>
