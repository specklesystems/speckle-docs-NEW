## Goal

Understand how project creation, publishing, versions, and loading fit together by publishing a small model of your own and reading it back.

## What you will build

In this optional deep dive, you will:

1. Paste the one-time SDK bootstrap (dependency injection setup you copy, not a concept you study)
2. Authenticate with Speckle Server
3. Create a project and model
4. Describe a wall and a door with a `BundleBuilder`
5. Publish them as a new version with `Send3`
6. Load the version back with `Receive3`

## When to use this

Use this page when you want the **full publish workflow** from scratch. For most AEC automation — loading connector-published models, QA checks, CSV exports — start with [Build your first model analysis tool](/developers/sdks/dotnet/guides/build-your-first-model-analysis-tool) instead. Creating data in code is less common in practice.

<Note>
  Updating a tour or script written for `Send` / `Receive` with `ServerTransport`, or `Send2` /
  `Receive2`? See [Migrate to 2026.9](/developers/sdks/dotnet/migrate-to-2026-9).
</Note>

## Prerequisites

1. **Install the package.** From your project directory, run:

```bash
dotnet add package Speckle.Sdk --version 2026.9.0-beta.7
```

You should see `<PackageReference Include="Speckle.Sdk" Version="2026.9.0-beta.7" />` in your `.csproj`. A later stable 2026.9.0 replaces the beta pin without changing the calls on this page.

2. **Get a personal access token.** In the web app, open the workspace switcher (the workspace name at the top of the left sidebar), select your name, then open **Developer** and create a token. See [Building with PATs](/developers/authentication/pats). You will paste it in Step 2 below.

## Full workflow

### Step 1: Bootstrap the SDK (copy once)

Register Speckle.Sdk once at startup.

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
using Microsoft.Extensions.DependencyInjection;
using Speckle.Sdk;

var services = new ServiceCollection();
services.AddSpeckleSdk(
    new Application("Quickstart", "quickstart"),
    "1.0.0",
    typeof(Speckle.Objects.Geometry.Point).Assembly
);
var provider = services.BuildServiceProvider();
var operations = provider.GetRequiredService<Speckle.Sdk.Api.IOperations>();
```

<Tip>
  This is **boilerplate**, not a DI tutorial. You are not expected to register your own services or
  understand container lifetimes. [Automate with
  scripts](/developers/sdks/dotnet/getting-started/scripts-and-notebooks) shows how to wrap this in
  a static helper for notebook cells and Grasshopper scripts.
</Tip>

### Step 2: Authenticate

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
using Speckle.Sdk.Api;
using Speckle.Sdk.Credentials;

var account = await provider.GetRequiredService<IAccountFactory>()
    .CreateAccount(new Uri("https://app.speckle.systems"), "your_token_here"); // Replace with your token

using var client = provider.GetRequiredService<IClientFactory>().Create(account);

Console.WriteLine($"✓ Authenticated as {account.userInfo.name}");
```

<Check>If this works, you'll see your name printed!</Check>

### Step 3: Create a project and model

Projects are the top-level containers for your data. A model holds the versions you publish.

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
using Speckle.Sdk.Api.GraphQL.Enums;
using Speckle.Sdk.Api.GraphQL.Inputs;

var project = await client.Project.Create(new ProjectCreateInput(
    "My First Speckle Project",
    "Learning Speckle.Sdk",
    ProjectVisibility.Private
));
var model = await client.Model.Create(new CreateModelInput("My first model", "This is my first model", project.id));

Console.WriteLine($"✓ Created project {project.id} and model {model.id}");
```

<Note>
  If the workspace plan is already at your maximum project limit, you'll need to delete some
  projects before creating a new one.
</Note>

### Step 4: Describe objects with a BundleBuilder

A `BundleBuilder` collects objects, their properties, their geometry, and the relations between them. Each object is identified by an application id you choose.

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
using Speckle.Objects.Geometry;
using Speckle.Sdk.Bundles;

using var builder = new BundleBuilder(
    new SpeckleApplication
    {
        HostApplication = "Quickstart",
        HostApplicationVersion = "1.0",
        Slug = "quickstart",
        SpeckleVersion = "1.0.0",
    },
    "m"
);

var walls = builder.GetOrAddContainerPath(["Level 1", "Walls"]);

var wall = builder.GetOrAddObject("wall-1").SetProperties(
    new Dictionary<string, object?>
    {
        ["Constraints"] = new Dictionary<string, object?> { ["Base Offset"] = 0.5 },
    },
    name: "Basic Wall"
);
wall.Collection = walls;
wall.AddGeometry(new Mesh { vertices = [0, 0, 0, 1, 0, 0, 0, 1, 0], faces = [3, 0, 1, 2], units = "m" });

var door = builder.GetOrAddObject("door-1").SetProperties(
    new Dictionary<string, object?> { ["Width"] = 0.9 },
    name: "Door"
);
door.Collection = walls;
door.Host = wall;

Console.WriteLine("✓ Described a wall and a door");
```

Nested property dictionaries become dotted paths: the wall's offset is stored as `Constraints.Base Offset`. `door.Host = wall` records a typed relation instead of nesting the door inside the wall. See [Object model](/developers/object-model/overview) and [Relations](/developers/object-model/relations).

### Step 5: Publish a version

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
var sent = await operations.Send3(account, project.id, model.id, builder, options: null, cancellationToken: default);
Console.WriteLine($"✓ Uploaded. Reserved version id: {sent.VersionId}");

var version = await operations.WaitForVersion(account, sent);
Console.WriteLine($"✓ Version ready: {version.id}");
Console.WriteLine($"View it: https://app.speckle.systems/projects/{project.id}/models/{model.id}");
```

`Send3` returns as soon as the upload finishes. The server then processes the bundle and creates the version. `WaitForVersion` waits for that, so the version exists before you load it in the next step.

<Check>Go to that URL to see the new version in the web app.</Check>

### Step 6: Load the version back

```csharp Example lines icon="/images/developers/sdks/csharp.svg"
using var received = await operations.Receive3(
    account,
    project.id,
    model.id,
    version.id,
    options: null,
    cancellationToken: default
);

var receivedWall = received.ObjectByApplicationId("wall-1")!;
var receivedDoor = received.ObjectByApplicationId("door-1")!;

Console.WriteLine($"✓ Loaded {received.Objects.Count} objects");
Console.WriteLine($"Wall offset: {receivedWall.GetDouble("Constraints.Base Offset")}");
Console.WriteLine($"Door is hosted by: {receivedDoor.Host?.Name}");
```

<Info>
  `Receive3` downloads the version's bundle to a scratch directory and returns a `Model`. Wrap it in
  `using` so the files are deleted when you are done.
</Info>

<Note>You've now completed your first full Speckle workflow with .NET.</Note>

## Complete example

```csharp Complete example lines icon="/images/developers/sdks/csharp.svg" expandable
using Microsoft.Extensions.DependencyInjection;
using Speckle.Objects.Geometry;
using Speckle.Sdk;
using Speckle.Sdk.Api;
using Speckle.Sdk.Api.GraphQL.Enums;
using Speckle.Sdk.Api.GraphQL.Inputs;
using Speckle.Sdk.Bundles;
using Speckle.Sdk.Credentials;

// 1. Register the SDK
var services = new ServiceCollection();
services.AddSpeckleSdk(new Application("Quickstart", "quickstart"), "1.0.0", typeof(Point).Assembly);
var provider = services.BuildServiceProvider();
var operations = provider.GetRequiredService<IOperations>();

// 2. Authenticate
var account = await provider.GetRequiredService<IAccountFactory>()
    .CreateAccount(new Uri("https://app.speckle.systems"), "your_token_here");
using var client = provider.GetRequiredService<IClientFactory>().Create(account);
Console.WriteLine($"✓ Authenticated as {account.userInfo.name}");

// 3. Create project and model
var project = await client.Project.Create(new ProjectCreateInput(
    "My First Speckle Project",
    "Learning Speckle.Sdk",
    ProjectVisibility.Private
));
var model = await client.Model.Create(new CreateModelInput("My first model", "This is my first model", project.id));

// 4. Describe objects
using var builder = new BundleBuilder(
    new SpeckleApplication
    {
        HostApplication = "Quickstart",
        HostApplicationVersion = "1.0",
        Slug = "quickstart",
        SpeckleVersion = "1.0.0",
    },
    "m"
);
var walls = builder.GetOrAddContainerPath(["Level 1", "Walls"]);
var wall = builder.GetOrAddObject("wall-1").SetProperties(
    new Dictionary<string, object?>
    {
        ["Constraints"] = new Dictionary<string, object?> { ["Base Offset"] = 0.5 },
    },
    name: "Basic Wall"
);
wall.Collection = walls;
wall.AddGeometry(new Mesh { vertices = [0, 0, 0, 1, 0, 0, 0, 1, 0], faces = [3, 0, 1, 2], units = "m" });
var door = builder.GetOrAddObject("door-1").SetProperties(
    new Dictionary<string, object?> { ["Width"] = 0.9 },
    name: "Door"
);
door.Collection = walls;
door.Host = wall;

// 5. Publish and wait for the version
var sent = await operations.Send3(account, project.id, model.id, builder, options: null, cancellationToken: default);
var version = await operations.WaitForVersion(account, sent);
Console.WriteLine($"✓ Version ready: {version.id}");
Console.WriteLine($"View: https://app.speckle.systems/projects/{project.id}/models/{model.id}");

// 6. Load it back
using var received = await operations.Receive3(
    account,
    project.id,
    model.id,
    version.id,
    options: null,
    cancellationToken: default
);
Console.WriteLine($"✓ Loaded {received.Objects.Count} objects");
Console.WriteLine($"Door is hosted by: {received.ObjectByApplicationId("door-1")?.Host?.Name}");
```

## FAQ

<AccordionGroup>
  <Accordion title="Should I use this quickstart or Automate with scripts?">
    Use **Automate with scripts** for Grasshopper, notebooks, and one-off automations that load
    existing models — it needs only the bootstrap and `Receive3`. Use **this quickstart** when you
    want to publish your own data and see the whole round trip.
  </Accordion>
  <Accordion title="Why does Send3 return before the version exists?">
    The server processes every upload before it creates the version. `Send3` returns a reserved
    version id when the upload finishes; the version appears when processing completes. Call
    `WaitForVersion` when the same script needs it. See [Publish through model
    ingestions](/developers/migration/publish-through-ingestions).
  </Accordion>
  <Accordion title="What happens if I call Send3 twice with the same builder?">
    It fails. `Send3` finishes the builder, so it cannot be reused. Create a new `BundleBuilder` for
    each version you publish.
  </Accordion>
  <Accordion title="I published but cannot find the version in the UI">
    Processing may still be running, or it failed. Wait for `WaitForVersion` to return; if it
    throws, the publish did not create a version and you should send again.
  </Accordion>
</AccordionGroup>
