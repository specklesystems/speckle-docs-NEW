When you define your own Speckle payloads in .NET — room data, survey results, or connector conversion output — you structure them as `Base` objects with typed or dynamic properties and optional detachment for large nested graphs. This guide covers creation, introspection, and when to detach.

## Prerequisites

- [Speckle.Sdk installed](/developers/sdks/dotnet/getting-started/installation)
- Familiarity with [Objects and Traversal](/developers/sdks/dotnet/concepts/objects-and-traversal)

## Complete Example

```csharp
using Speckle.Sdk.Models;

public class Room : Base
{
    public required string name { get; set; }
    public double area { get; set; }

    [DetachProperty]
    public List<Base>? elements { get; set; }
}

var room = new Room { name = "Conference Room A", area = 32.5 };

// Dynamic properties — no class definition needed
room["material"] = "Concrete";
room["fireRating"] = "2 hour";

room.elements = new List<Base>();
for (var i = 0; i < 3; i++)
{
    var chair = new Base();
    chair["name"] = $"Chair {i}";
    chair["category"] = "Furniture";
    room.elements.Add(chair);
}

// Discover every property, typed and dynamic
foreach (var (key, value) in room.GetMembers())
{
    Console.WriteLine($"{key}: {value}");
}
```

## Step-by-Step Explanation

### Typed vs. Dynamic Properties

Use a typed subclass when you control the shape of the data and want compile-time safety:

```csharp
public class Room : Base
{
    public required string name { get; set; }
    public double area { get; set; }
}
```

Use the plain `Base` class with the indexer when the shape is unknown ahead of time, or you're adding a handful of ad hoc properties to an object you don't own:

```csharp
var obj = new Base();
obj["name"] = "Widget";
obj["value"] = 42;
```

Both approaches produce the same wire format — `speckle_type` and typed properties are just reflected into the same property bag that dynamic properties live in.

<Warning>
Avoid dynamic property names starting with `_` (ignored by convention) or a `@` prefix unless you intend to [detach](#detachment) that property. A double `@@` prefix or a name containing `.` or `/` throws `InvalidPropNameException`.
</Warning>

### Discovering Properties at Runtime

`Base` doesn't expose a plain list of property names — use `GetMembers()` (typed + dynamic, as a dictionary) or `GetDynamicMemberNames()` (names only):

```csharp
using Speckle.Sdk.Models;

// All properties (typed and dynamic) as a dictionary
foreach (var (key, value) in someObject.GetMembers())
{
    Console.WriteLine($"{key} = {value}");
}

// Just the names
foreach (var name in someObject.GetDynamicMemberNames())
{
    Console.WriteLine(name);
}

// Only the dynamically-added keys (excludes typed properties)
foreach (var key in someObject.DynamicPropertyKeys)
{
    Console.WriteLine(key);
}
```

`GetMembers` accepts a `DynamicBaseMemberType` flag (`Instance`, `Dynamic`, `Obsolete`) if you need to filter which kind of property is included — the default includes typed instance properties and dynamic properties, but not obsolete ones.

### Safe Access Patterns

Speckle objects can arrive from different senders with different schemas. Don't assume a property exists:

```csharp
// Indexer returns null for missing properties — no exception
var material = obj["material"] as string ?? "Unknown";

// BaseExtensions helpers for common lookups
var name = obj.TryGetName() ?? "Unnamed";
var displayValue = obj.TryGetDisplayValue(); // null if none
```

### Detachment

By default, nested `Base` objects are serialized inline with their parent. Mark a property for **detachment** to store it as a separate object, referenced by ID — useful for large or shared substructures:

```csharp
public class Room : Base
{
    [DetachProperty]
    public List<Base>? elements { get; set; }
}
```

For dynamic properties, prefix the key with `@` instead of using an attribute:

```csharp
obj["@heavyGeometry"] = mesh;
```

<Info>
`GetDetachedPropName` and the paired `GetDetachedProp`/`SetDetachedProp` extension methods let you read or write a property without knowing whether it's a typed or dynamic detached property — useful when writing code that works across object types you don't control.

```csharp
using Speckle.Sdk.Models.Extensions;

obj.SetDetachedProp("elements", myElements);
var elements = obj.GetDetachedProp("elements");
```
</Info>

### Chunking

For very large lists (thousands of primitive values), combine `[DetachProperty]` with `[Chunkable]` to split the list across multiple stored objects instead of one large one:

```csharp
[DetachProperty]
[Chunkable(1000)]
public List<double>? vertices { get; set; }
```

## Common Pitfalls

<AccordionGroup>
  <Accordion title="InvalidPropNameException when setting a dynamic property">
    The key is empty, starts with `@@`, or contains `.`/`/`. Use `IsPropNameValid` to check before setting if the key comes from untrusted input.
  </Accordion>
  <Accordion title="obj.id is null right after construction">
    `id` is only populated after the object has been sent or deserialized — it's a content hash, not something you set. See [Object IDs (Hashes)](/developers/sdks/dotnet/concepts/overview#object-ids-hashes).
  </Accordion>
  <Accordion title="Setting obj['id'] doesn't do what you expect">
    `id`, `speckle_type`, and other reserved names have special meaning. Use your own property names (`elementId`, not `id`) for custom identifiers.
  </Accordion>
  <Accordion title="Detached property comes back null after receive">
    Confirm the property was marked with `[DetachProperty]` (typed) or an `@` prefix (dynamic) on the sending side — detachment must be set before sending, not after.
  </Accordion>
</AccordionGroup>
