## Goal

Send derived analysis results — QA flags, health checks, computed metadata — back to Speckle Server as a new published version.

## What you will build

A script that loads a model with `Receive3`, checks each object for a category and a level, records the result as `qaStatus` and `missingProperties` on a new object per source element, and publishes the report to a separate model with `Send3`.

## When to use this

Use this when you want analysis output **visible in Speckle** for the team — model health dashboards, QA pass/fail flags, or computed fields from Grasshopper or a console tool.

Avoid this when a local CSV is enough — see [Export model data to CSV](/developers/sdks/dotnet/guides/export-model-data-to-csv).

## Recommended approach

1. Load the source model with `Receive3`
2. Check each object with `GetString` and relation accessors such as `Level`
3. Describe the results in a `BundleBuilder`, one object per source element
4. Publish to a separate report model with `Send3`, then `WaitForVersion`
5. Use `Send3` — not `SendPipeline` unless you are building a connector

## Complete example

The example assumes the [bootstrap](/developers/sdks/dotnet/getting-started/scripts-and-notebooks), an `account`, and `projectId`, `sourceModelId`, `versionId`, and `reportModelId` are already in scope.

```csharp Complete example lines icon="/images/developers/sdks/csharp.svg" expandable
using Speckle.Sdk;
using Speckle.Sdk.Bundles;

using var source = await SpeckleBootstrap.Operations.Receive3(
    account,
    projectId,
    sourceModelId,
    versionId,
    options: null,
    cancellationToken: default
);

using var builder = new BundleBuilder(
    new SpeckleApplication
    {
        HostApplication = "QA Script",
        HostApplicationVersion = "1.0",
        Slug = "qa-script",
        SpeckleVersion = "1.0.0",
    },
    "m"
);
var passed = builder.GetOrAddContainerPath(["Model health check", "Pass"]);
var failed = builder.GetOrAddContainerPath(["Model health check", "Fail"]);

var failures = 0;
foreach (var obj in source.Objects)
{
    var missing = new List<string>();
    if (obj.GetString("category") is null)
    {
        missing.Add("category");
    }
    if (obj.Level is null)
    {
        missing.Add("level");
    }

    var result = builder.GetOrAddObject(obj.ApplicationId).SetProperties(
        new Dictionary<string, object?>
        {
            ["sourceApplicationId"] = obj.ApplicationId,
            ["qaStatus"] = missing.Count == 0 ? "pass" : "fail",
            ["missingProperties"] = string.Join("; ", missing),
        },
        name: obj.Name ?? obj.ApplicationId
    );
    result.Collection = missing.Count == 0 ? passed : failed;
    failures += missing.Count == 0 ? 0 : 1;
}

var sent = await SpeckleBootstrap.Operations.Send3(
    account,
    projectId,
    reportModelId,
    builder,
    new SendOptions(Message: "QA report from automation"),
    cancellationToken: default
);
var version = await SpeckleBootstrap.Operations.WaitForVersion(account, sent);

Console.WriteLine($"Published version {version.id}: {source.Objects.Count} results, {failures} failures");
```

You should see the new version id and the result counts. If `Receive3` throws because the source version has no bundle, it was published before 2026.9 and not converted: see [Read versions published before 2026.9](/developers/sdks/dotnet/migrate-to-2026-9#read-versions-published-before-2026-9).

<Warning>
  `Send3` returns as soon as the upload finishes, with a reserved version id. The version exists
  only when the server finishes processing, so call `WaitForVersion` before you link to or load it.
</Warning>

## How it works

**Analysis stays local until you publish.** `Receive3` gives you a `Model` to query, and your rules run in memory. `BundleBuilder` writes the results to local files as you add them; `Send3` uploads them, and the server creates the version.

The report objects carry properties only, with no geometry to render. Add geometry with `AddGeometry` if the report should show in the viewer.

## Common mistakes

| Mistake                                        | Fix                                                             |
| ---------------------------------------------- | --------------------------------------------------------------- |
| Reading the new version straight after `Send3` | Call `WaitForVersion` first                                     |
| Publishing to the source model                 | Publish reports to a separate model, so they don't replace it   |
| Using `SendPipeline` for a small report        | `Send3` is the publish path for scripts                         |
| Reusing a `BundleBuilder` after `Send3`        | `Send3` finishes the builder; create a new one for each publish |
| Sending the entire source model back unchanged | Publish only the analysis payload                               |
